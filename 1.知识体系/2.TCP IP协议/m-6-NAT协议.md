# NAT 协议详解

## 1. NAT 产生背景

### 1.1 IPv4 地址枯竭与内网地址复用

IPv4 地址长度为 32 位，理论约 43 亿个。随着设备数量爆炸式增长，**公网 IPv4 地址早已分配殆尽**（IANA 于 2011 年分配完最后一段地址池）。NAT（Network Address Translation，网络地址转换，RFC 1631）的核心思路是：**内部网络复用私网地址，仅在出口设备上把私网地址映射为公网地址**，让整个家庭或企业只需一个（或少量）公网 IP。

RFC 1918 划分了三段**私有地址**，任何机构内部均可重复使用：

| 网段 | 前缀 | 范围 | 可用主机数 |
|------|------|------|-----------|
| A 类 | 10.0.0.0/8 | 10.0.0.0 – 10.255.255.255 | 约 1677 万 |
| B 类 | 172.16.0.0/12 | 172.16.0.0 – 172.31.255.255 | 约 104 万 |
| C 类 | 192.168.0.0/16 | 192.168.0.0 – 192.168.255.255 | 约 6.5 万 |

私有地址只在内部使用，公网**不允许路由**（ISP 会丢弃），因此内网设备必须经出口设备 NAT 后才能访问互联网。

### 1.2 NAT 解决了什么、牺牲了什么

| 解决的问题 | 付出的代价 |
|-----------|-----------|
| 大幅缓解 IPv4 地址枯竭，多台设备共享一个公网 IP | 破坏**端到端透明性**，修改 IP 头、端口与校验和 |
| 内网设备对外隐藏，天然提供一层"伪防火墙" | 外部主动访问内网困难，P2P 应用需穿透 |
| 更换运营商/公网 IP 时内网无需改动 | 部分携带 IP 的协议（FTP、SIP）需 ALG 配合 |
| 平滑过渡，无需全网络改造 IPv6 | 增加设备处理负担，成为性能与故障点 |

## 2. NAT 的四种基本类型

### 2.1 类型总览

| 类型 | 全称 | 转换对象 | 典型命令 | 典型应用 |
|------|------|---------|---------|---------|
| SNAT | Source NAT（源地址转换） | 出站报文**源 IP** | `-t nat -A POSTROUTING -j SNAT --to 公网IP` | 内网上网共享 |
| MASQUERADE | 伪装（SNAT 变种） | 同上，但自动取出口 IP | `-t nat -A POSTROUTING -j MASQUERADE` | 动态 IP（PPPoE）上网 |
| DNAT | Destination NAT（目的地址转换） | 入站报文**目的 IP** | `-t nat -A PREROUTING -j DNAT --to 内网IP` | 端口映射、服务器发布 |
| PAT | Port Address Translation（端口地址转换） | 同时改 IP 与端口 | 由 SNAT/DNAT 加 `--to-ports` 实现 | 多对一共享上网 |
| 双向 NAT | 同时做 SNAT + DNAT | 双向都转换 | 上述规则组合 | 地址段重叠、负载均衡 |

### 2.2 SNAT：源地址转换

**作用**：修改**出站**数据包的源 IP，使内网私网地址以公网地址出现在公网上。

```
内网 PC (192.168.1.10) ──► 出口路由器 ──► 公网服务器 (8.8.8.8)
    src 192.168.1.10         │
    dst 8.8.8.8              │  SNAT: src 改为 1.2.3.4
                             ▼
    src 1.2.3.4 ───────────────────────────► 8.8.8.8
```

- 在路由决策之后、报文离开设备的 **POSTROUTING** 链执行
- 转换后须同步更新连接跟踪表，并重算 IP 校验和（改了端口还要重算 TCP/UDP 校验和）
- 典型配置：`iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -o eth0 -j SNAT --to-source 1.2.3.4`
- 适用于出口公网 IP **固定**的场景

### 2.3 MASQUERADE：伪装（SNAT 的动态版）

MASQUERADE 本质是 SNAT，区别在于**源地址不写死**，而是自动取"报文从哪个接口出去，就用哪个接口的 IP"。

- 典型配置：`iptables -t nat -A POSTROUTING -o ppp0 -j MASQUERADE`
- 适用于出口公网 IP **动态变化**的场景（PPPoE 拨号、DHCP 获取公网地址）
- 换线重拨后 IP 变了无需改规则，SNAT 则要重新配置；代价是每个连接都要查询出口 IP，性能略低

### 2.4 DNAT：目的地址转换（端口映射）

**作用**：修改**入站**数据包的**目的 IP 和目的端口**，把公网访问"转发"到内网服务器。

```
公网用户 (1.2.3.5) ──► 路由器(1.2.3.4:8080) ──► 内网 Web 服务器 (192.168.1.20:80)
    src 1.2.3.5            │  DNAT: dst 改为 192.168.1.20:80
    dst 1.2.3.4:8080       ▼
                           ──────────────────────────► 192.168.1.20:80
```

- 在路由决策**之前**、报文进入设备的 **PREROUTING** 链执行
- 典型配置：`iptables -t nat -A PREROUTING -d 1.2.3.4 -p tcp --dport 8080 -j DNAT --to-destination 192.168.1.20:80`
- 通常 DNAT 与 SNAT **成对出现**：回程报文目的地址是内网私网 IP，需再经 SNAT 把源地址换成路由器地址，内网设备才会回包（即双向 NAT）

### 2.5 PAT：端口地址转换

PAT 是 NAT 的"端口级"扩展，**多个内网地址映射到同一个公网 IP，用不同端口区分**。

- 传输层端口只有 65535 个，理论上一个公网 IP 最多承载约 6.5 万并发映射
- 例：`192.168.1.10:12345`、`192.168.1.11:23456` 分别映射到 `1.2.3.4:50001`、`1.2.3.4:50002`
- 依赖**连接跟踪（conntrack）**，因此 ICMP、GRE 等无端口协议可用"协议+ID"类似方式复用

### 2.6 双向 NAT（twice NAT）

同时修改**源地址与目的地址**，用于内外部地址段**重叠**（如两侧都用 192.168.1.0/24）或双向映射：外部主机访问内部主机时，PREROUTING 把目的地址改为真实内网地址，POSTROUTING 把源地址伪造成一个内网侧的对应地址，实现地址平移。

- 需在 PREROUTING（DNAT）与 POSTROUTING（SNAT）同时配置规则
- 也常用于**地址平移**：内网地址段整体映射到另一段公网地址，不做端口复用

## 3. NAT 转换表

NAT 设备维护一张**连接跟踪表（conntrack table）**，记录每条连接的映射关系：

| 方向 | 内部（私网）侧 | 外部（公网）侧 | 协议 |
|------|---------------|---------------|------|
| 出站 | 192.168.1.10 : 12345 | 1.2.3.4 : 40001 | TCP |
| 出站 | 192.168.1.11 : 23456 | 1.2.3.4 : 40002 | UDP |
| 出站 | 192.168.1.12 : 34567 | 1.2.3.4 : 40003 | ICMP（用 ICMP ID 区分） |
| 入站 | 192.168.1.20 : 80 | 1.2.3.4 : 8080 | TCP |

| 核心字段 | 说明 |
|------|------|
| 原始方向（original） | 内网设备的 src IP/端口 → 外网目的 IP/端口 |
| 回复方向（reply） | 改写后的公网 src IP/端口 → 实际目的 IP/端口 |
| 协议状态 | TCP 的 ESTABLISHED/TIME_WAIT 等，用于老化回收 |
| 超时时间 | 不活跃表项被清除，回收映射资源 |

> 转换表是 NAT 的"状态记忆"：靠它，公网服务器回包时 NAT 设备才知道转发给哪台内网主机。**没有回程记录，就无法双向通信。**

## 4. 圆锥型 NAT 分类（NAT 行为模型）

根据**对入站报文的映射复用程度**，NAT 分为四种行为（RFC 3489 / RFC 4787），直接影响 P2P 穿透难度：

| 类型 | 英文 | 出站映射 | 外部主机访问条件 | 穿透难度 |
|------|------|---------|-----------------|---------|
| 全锥型 | Full Cone | 同一内网 IP:Port 复用同一外部映射 | 任何外部主机、任何端口都可访问 | 最容易 |
| 限制锥型 | Restricted Cone | 同一内网 IP:Port 复用 | 仅**之前被该内网主机访问过**的外部 IP 可访问 | 中等 |
| 端口限制锥型 | Port Restricted Cone | 同一内网 IP:Port 复用 | 仅之前访问过的**外部 IP:Port** 可访问 | 较难 |
| 对称型 | Symmetric NAT | 每目的 IP:Port 生成**独立**外部映射 | 外部无法访问，除非事先知道对应映射 | 最难，几乎不可穿透 |

### 4.1 关键区别：复用 vs 独立

- **锥型（Cone）NAT**：内网 `IP:Port` 与外部映射**一对一复用**，去往任何目的地外部端口都保持不变，打一个洞即可持续回访
- **对称型 NAT**：同一内网 `IP:Port` 发往**不同目的地址**会生成**不同**外部端口，P2P 双方即使拿到对方映射地址也无法打通

```
例：内网主机 192.168.1.10:5000
  锥型：  → 8.8.8.8:53  映射 1.2.3.4:10000
         → 9.9.9.9:53  映射 1.2.3.4:10000   （端口复用）
  对称：  → 8.8.8.8:53  映射 1.2.3.4:10001
         → 9.9.9.9:53  映射 1.2.3.4:10002   （每次不同）
```

- 家庭宽带多为锥型或端口限制锥型；部分运营商（尤其移动网络）使用对称型 NAT，P2P 只能借助 TURN 中继

## 5. NAT 穿透方案

### 5.1 方案对比

| 方案 | 原理 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|---------|
| STUN | 客户端询问服务器"我看到的公网 IP:Port" | 实现简单，不经服务器转发，延迟低 | 对对称型 NAT 无效 | 锥型 NAT 下 P2P 打洞 |
| TURN | 服务器**中继转发**全部媒体数据 | 任何 NAT 下都能连通 | 消耗服务器带宽，延迟高 | 对称型 NAT、无法直连时兜底 |
| ICE | STUN+TURN 综合候选地址，择优连接 | 自动选最优路径，容错强 | 实现复杂 | WebRTC、VoIP 等实时通信 |
| UPnP/NAT-PMP | 主动向路由器**申请**端口映射 | 直接建立稳定映射，无需打洞 | 需路由器支持；有安全风险 | 主机游戏、BT、远程访问 |
| ALG | 网关**识别并改写**应用层携带的 IP/端口 | 让 FTP/SIP 等协议穿过 NAT | 需逐协议适配，实现复杂易出漏洞 | FTP、SIP、PPTP 等特殊协议 |
| 端口触发 | 内网出站"触发"某端口，路由器自动放行对应入站映射 | 免配置、按需开放 | 同时一般只支持一台主机 | 游戏主机、特定应用 |

### 5.2 STUN / TURN / ICE

- **STUN（RFC 5389）**：客户端向公网 STUN 服务器发请求，服务器从报文源地址得知该连接经 NAT 映射后的公网 `IP:Port`，客户端再用它尝试与对端直连（打洞）。局限：只能探明地址，**无法绕过**对称型 NAT
- **TURN（RFC 5766）**：客户端在服务器上申请**中继地址**，所有数据经服务器转发，对端无需穿透，**任何 NAT 都能通信**。代价：流量全走服务器，带宽成本高、时延大，通常作 ICE 的**最后兜底**
- **ICE（RFC 8445）**：收集本机地址、STUN 映射地址、TURN 中继地址三类候选，通过连通性检测**择优连接**。典型顺序：本机直连 > 打洞直连 > TURN 中继，是 WebRTC、SIP 语音的标准做法

### 5.3 UPnP / NAT-PMP / PCP

- **UPnP IGD**：客户端通过 SOAP 请求向路由器添加端口映射，实现"免配置端口转发"
- **NAT-PMP**：Apple 主推的简化版，UDP 5351 端口，请求外部端口映射
- **PCP（RFC 6887）**：NAT-PMP 的继任者，支持 IPv4/IPv6、端口与前缀映射
- 注意：若路由器为对称型 NAT，UPnP 映射对每个目的地址也需独立映射，仍可能失败

### 5.4 ALG（应用层网关）

FTP、SIP、RTSP、PPTP 等协议的报文中**携带 IP 地址或端口**（如 FTP 的 PORT 命令），普通 NAT 只改 IP 头会导致协议失效。ALG 在 NAT 设备上**解析并同步改写**应用层字段：

- FTP：改写 PORT/PASV 命令中的 IP:Port，并预先建立对应数据连接映射
- SIP：改写 SDP 中的 IP:Port，处理 Via/Contact 字段
- 现代方案：改用 STUN/ICE 替代（SIP over UDP 用 ICE 后常关闭 ALG，避免双重转换出错）

### 5.5 端口触发（Port Triggering）

- 内网主机向**触发端口**发起出站连接后，路由器自动打开预先定义的**入站端口范围**，映射到该主机
- 相比静态端口映射**按需开放、用完即收**，同一映射通常只服务一台主机
- 常用于家用路由器的游戏主机、多台设备需要同一端口映射的场景

## 6. Linux 中 iptables 实现 NAT

### 6.1 数据包流向与 NAT 链

NAT 只在两个链生效：**PREROUTING（DNAT）** 与 **POSTROUTING（SNAT/MASQUERADE）**。

```
入站报文 ──► PREROUTING ──► 路由决策 ──► FORWARD ──► POSTROUTING ──► 出站
（DNAT）                     │   ▲        （转发）    （SNAT）
                            ▼   │
                        本机 INPUT ──► 本地进程     本机 OUTPUT ──► 路由决策 ──► POSTROUTING
```

| 链 | 时机 | 可用的 NAT 动作 |
|----|------|----------------|
| PREROUTING | 报文**进入设备**、路由决策之前 | DNAT（改目的地址） |
| POSTROUTING | 报文**离开设备**、路由决策之后 | SNAT、MASQUERADE（改源地址） |

### 6.2 常用命令示例

```bash
# 1. 内网共享上网（固定公网 IP 1.2.3.4）
iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -o eth0 -j SNAT --to-source 1.2.3.4

# 2. PPPoE 动态 IP 共享上网（自动取 ppp0 的 IP）
iptables -t nat -A POSTROUTING -o ppp0 -j MASQUERADE

# 3. 端口映射：公网 8080 → 内网 192.168.1.20:80
iptables -t nat -A PREROUTING -d 1.2.3.4 -p tcp --dport 8080 \
         -j DNAT --to-destination 192.168.1.20:80

# 4. 回程回包（配合 3，源地址换成路由器地址，内网主机才会回包）
iptables -t nat -A POSTROUTING -s 192.168.1.20 -o eth0 -j MASQUERADE

# 5. 查看 NAT 表与连接跟踪
iptables -t nat -L -n -v
cat /proc/net/nf_conntrack
conntrack -L          # 需安装 conntrack 工具
```

### 6.3 关键要点

- NAT 规则必须加 `-t nat` 表（默认表是 filter）；只有**新连接的第一个包**才匹配 NAT 规则建立映射，后续报文靠 conntrack 按映射转发
- 转发流量需在 **FORWARD 链**放行（`-m conntrack --ctstate ESTABLISHED,RELATED`），否则被挡
- 需加载内核模块：`modprobe nf_nat` 等

## 7. SNAT 与 MASQUERADE 的区别

| 对比项 | SNAT | MASQUERADE |
|--------|------|------------|
| 转换地址来源 | 规则中**显式指定** `--to-source` | **自动取出口接口**的当前 IP |
| 适用场景 | 出口公网 IP **固定**（专线、静态公网） | 出口 IP **动态变化**（PPPoE、DHCP） |
| 换 IP 后的处理 | 需手工修改规则 | 无需修改，自动适应新 IP |
| 性能 | 稍快（直接使用配置地址） | 稍慢（每个连接查询出口 IP） |
| 典型命令 | `SNAT --to-source 1.2.3.4` | `MASQUERADE`（不带参数） |

> 结论：**固定 IP 用 SNAT，动态 IP 用 MASQUERADE**。家用路由器拨号用 MASQUERADE，企业专线常用 SNAT。

## 8. NAT 对端到端通信的影响与局限

| 影响 | 说明 |
|------|------|
| 破坏端到端原则 | 内网主机对外不透明，外部无法主动发起连接，需端口映射或穿透 |
| P2P 通信困难 | 双方都在 NAT 后面无法直接互通，需 STUN/ICE/TURN 辅助 |
| 协议兼容性问题 | 携带 IP/端口信息的应用层协议（FTP、SIP、H.323）需 ALG 或穿透方案 |
| IP 分片问题 | 改写 IP 头导致**分片校验和失效**，UDP 分片（大 DNS 应答）可能被丢弃 |
| 性能与连接数限制 | 每包查表、改写头、重算校验和；端口约 6.5 万上限，运营商级 CGNAT 更甚 |
| 安全性局限 | NAT 不是真正的防火墙，存在 UDP 打洞、DNS 重绑定等绕过风险，不应替代防火墙 |

### 8.1 NAT 与 IPv6

- IPv6 地址充足，理论上可恢复端到端透明通信，**无需 NAT**
- 但现实中仍有 **NPTv6**（前缀翻译，RFC 6296）等用于地址平移、双栈共存、隐藏内部拓扑
- 家用 IPv6 常用 **SLAAC + DHCPv6-PD** 直接分配全球单播地址，避免 NAT

### 8.2 典型故障排查思路

| 现象 | 可能原因 | 排查方向 |
|------|---------|---------|
| 内网上网正常，外部访问内网服务失败 | 未配置 DNAT 端口映射 | 检查 PREROUTING 规则与 conntrack 表 |
| 端口映射配了仍不通 | 缺回程 SNAT，或 FORWARD 链丢弃 | 检查 POSTROUTING、FORWARD 放行状态 |
| 大文件上传/下载偶发失败 | UDP 分片被 NAT 丢弃 | 调整 MTU/PMTUD |
| FTP 被动模式无法连接 | 报文内 IP 未改写 | 启用 FTP ALG 或改用 SFTP |
| P2P 打洞失败 | 运营商为对称型 NAT | 换用 TURN 中继，或申请公网 IP |

## 9. 小结

- **背景**：IPv4 地址枯竭 + RFC 1918 私网地址复用，催生了 NAT
- **四类 NAT**：SNAT（出站改源）、DNAT（入站改目的）、PAT（端口复用）、双向 NAT（源目都改）
- **转换表**：conntrack 记录 内部 IP:Port ↔ 外部 IP:Port 映射，是 NAT 双向通信的基础
- **四种行为**：Full Cone / Restricted Cone / Port Restricted Cone / Symmetric NAT，决定穿透难度
- **穿透方案**：STUN 探地址打洞、TURN 中继兜底、ICE 择优组合、UPnP/NAT-PMP 主动映射、ALG 改应用层、端口触发按需开放
- **Linux 实现**：`iptables -t nat`，PREROUTING 做 DNAT，POSTROUTING 做 SNAT/MASQUERADE；固定 IP 用 SNAT，动态 IP 用 MASQUERADE
- **局限**：破坏端到端、P2P 难穿透、协议兼容与分片问题；IPv6 是终极解决方案
