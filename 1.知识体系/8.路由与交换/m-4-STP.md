# STP工作原理
STP主要用于在存在环路结构的二层网络中构建一个无环的树形的二层拓扑，802.1D   
802.1w为快速生成树协议RSTP   

## 基本术语
1. 根桥
2. 根端口
3. 指定端口
4. 路径开销
5. 预备端口

## 生成树的工作原理
1. 根桥选举 -- 针对交换机
2. 根端口选举 -- 针对端口
3. 指定端口选举 -- 针对网段
4. 阻塞预备端口

## 生成树的端口状态
DIsabled、Blocking、Listening、Learning、Forwarding   

### STP 五种端口状态

| 状态 | 接收 BPDU | 发送 BPDU | 学习 MAC | 转发数据 | 进入条件 |
|------|-----------|-----------|----------|----------|----------|
| Disabled | 否 | 否 | 否 | 否 | 端口关闭/故障 |
| Blocking | 是 | 否 | 否 | 否 | 阻塞的预备端口，初始状态 |
| Listening | 是 | 是 | 否 | 否 | 端口参与选举，等待成为根/指定端口 |
| Learning | 是 | 是 | 是 | 否 | 监听期结束，学习 MAC 避免泛洪 |
| Forwarding | 是 | 是 | 是 | 是 | 正常转发状态 |

端口从 Blocking 到 Forwarding 需要经历 Listening（15s）+ Learning（15s），每个阶段由**转发延迟定时器（Forward Delay）**控制，这就是 STP 收敛慢的根本原因。

### STP 三个关键定时器

| 定时器 | 默认值 | 作用 |
|--------|--------|------|
| Hello Time | 2s | BPDU 发送间隔 |
| Forward Delay | 15s | Listening/Learning 状态的停留时间 |
| Max Age | 20s | 根桥失效判定，超过未收到 BPDU 则认为链路故障 |

正常情况下从链路故障到网络恢复转发需约 30~50 秒，业务中断明显，因此有了 RSTP。

## 总结
1. 根端口是交换机用来找根的。   
2. 指定端口是交换机用来喂数据给别人的。   
3. 只有这两种端口是通的，其他的都被堵上了，所以没有环路。   

# BPDU报文
STP生成树的计算，根端口、指定端口的选举，都是借助BPDU报文进行信息的传递和交换。包含 配置BPDU和拓扑改变BPDU两种   
BPDU报文采用IEEE 802.3的封装格式，以多播的方式发送，多播地址为：0180c2000000，默认2s发送一次   

## BPDU 字段
配置 BPDU 携带的关键字段：根桥 ID（优先级+MAC）、根路径开销、发送桥 ID、发送端口 ID、定时器参数、拓扑变化标志。接收方据此判断"谁的根更优"，选举出唯一根桥并计算到根的最短路径。

# RSTP
快速生成树协议RSTP是STP的升级版，加快了收敛速度   
RSTP的计算过程和STP的基本计算过程一样，不同在于：对于既不是根端口也不是指定端口的交换机端口，RSTP定义了备份端口和预备端口   
备份端口：如果该端口所连接的网段的指定交换机为此端口所属的交换机，为了备份指定端口：当指定端口出故障时，备份端口会立即接管，成为该网段新的指定端口。   
预备端口：如果该端口所连接的网段的指定交换机不是此端口所属的交换机，为了备份根端口：当根端口所在的链路断开时，预备端口会立即晋升为新的根端口，开始转发数据。   

## 端口状态
Discarding、Learning、Forwarding   

## RSTP 快速收敛机制

RSTP 把五种状态合并为三种（Discarding 合并 Disabled/Blocking/Listening），收敛时间从秒级降到**亚秒级**，靠四个机制实现：

### 1. Proposal/Agreement 握手

链路启用时，指定端口主动发 Proposal 请求，对端根端口回 Agreement 确认。通过两设备间的显式握手立即进入转发状态，**不再依赖 Forward Delay 倒计时**。

### 2. 边缘端口

连接终端的端口配置为边缘端口（edge port），直接从 Discarding 进入 Forwarding，不参与生成树计算。终端上线下线（如电脑开关机）不会触发拓扑变更。注意若边缘端口意外收到 BPDU 会自动转为普通端口。

### 3. P/A 收敛下的根端口快速切换

根端口故障时，预备端口检测到断链后**立即**进入转发状态（点对点链路场景），无需经过 Listening/Learning。

### 4. 拓扑变化传播改进

RSTP 只在收到 TC 时清空相关 MAC 地址表，不像 STP 那样周期性泛洪 TC 通知，减少无谓的 MAC 刷新。

| 对比项 | STP | RSTP |
|--------|-----|------|
| 标准 | 802.1D | 802.1w |
| 端口状态数 | 5 种 | 3 种 |
| 端口角色 | 根/指定/预备 | 根/指定/预备/备份 |
| 收敛时间 | 30~50s | 亚秒级 |
| 依赖定时器 | 强依赖 | 弱依赖，靠握手

# MSTP
多生成树协议MSTP用于解决启用了VLAN的交换网络中的环路问题   
MSTP允许将一个或多个VLAN映射到一个多生成树实例上，MSTP为每个多生成树实例单独计算根交换机，单独设置端口状态，即在网络中计算多个生成树。每个多生成树实例都是用单独RSTP算法，计算单独的生成树。
