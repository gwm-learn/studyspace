# ARP 地址解析协议

> ARP（Address Resolution Protocol）工作在网络层与链路层之间，负责把 IPv4 地址解析为 MAC 地址。链路层寻址一节还提到，同一子网内、跨子网两种场景下 ARP 的使用方式不同，本文做完整梳理。

## 为什么需要 ARP

- IP 地址是**逻辑地址**，跨网络可达；MAC 地址是**物理地址**，只在同一链路内有效。
- 数据帧在链路上传输时，二层头必须填目的 MAC。发送方不知道目的 MAC 就无法封装以太网头。
- ARP 的作用就是在同一个广播域内，根据目标 IP 查找目标 MAC。

## ARP 报文格式

| 字段 | 长度 | 说明 |
|------|------|------|
| 硬件类型 | 2 字节 | 1 表示以太网 |
| 协议类型 | 2 字节 | 0x0800 表示 IP 协议 |
| 硬件地址长度 | 1 字节 | MAC 地址长度 6 |
| 协议地址长度 | 1 字节 | IP 地址长度 4 |
| 操作码 | 2 字节 | 1=ARP 请求，2=ARP 应答，3=RARP 请求，4=RARP 应答 |
| 发送方 MAC | 6 字节 | 发起方硬件地址 |
| 发送方 IP | 4 字节 | 发起方协议地址 |
| 目标 MAC | 6 字节 | 请求时全 0 |
| 目标 IP | 4 字节 | 要解析的地址 |

以太网封装：ARP 报文直接承载在以太网帧中，帧头类型字段为 0x0806。ARP 请求的目标 MAC 用广播地址 `FF:FF:FF:FF:FF:FF`，应答为单播。

## ARP 工作过程

### 同一子网内

1. 主机 A 要向主机 B 发包，先查本地 ARP 缓存，没有 B 的条目。
2. A 广播发送 ARP 请求："谁的 IP 是 B，请把 MAC 告诉我"。
3. 子网内所有主机收到广播，只有 B 发现 IP 匹配，单播回复 ARP 应答。
4. A 收到应答，把 B 的 IP-MAC 映射写入缓存，然后封装数据帧发送。

### 跨子网（借助网关）

主机 A 判断目标 IP 不在本子网，不直接解析目标 IP，而是：

1. A 向**默认网关**（路由器）发 ARP 请求，解析网关的 MAC。
2. A 把数据帧发给网关，帧头目的 MAC 是网关的 MAC，帧内 IP 包目的 IP 仍是最终目标。
3. 网关收到后根据路由表转发：若目标在网关直连子网，网关再发 ARP 请求解析目标主机的 MAC，重新封装发送。

## ARP 缓存与老化

Linux 下用 `ip neigh`（或 `arp -a`）查看 ARP 缓存，缓存条目有状态：

| 状态 | 含义 |
|------|------|
| REACHABLE | 最近确认可达，直接用缓存 |
| STALE | 超过一定时间未用，下次使用需重新验证 |
| DELAY | STALE 后第一次使用，发送探测前的小等待窗口 |
| PROBE | 已发送 ARP 请求等待应答 |
| INCOMPLETE | 请求已发，等待目标应答 |
| FAILED | 多次请求无应答，解析失败 |

缓存条目通常几分钟内老化，避免 IP 变化后仍指向旧 MAC。

## 常见问题

### 1. ARP 欺骗 / 中间人攻击

攻击者伪造 ARP 应答，把网关 IP 对应到自己的 MAC，使受害者所有流量经过攻击者。防护手段：静态 ARP 绑定、DAI（Dynamic ARP Inspection，交换机开启端口绑定校验）。

### 2. ARP 泛洪

大量伪造源 IP 的 ARP 请求会撑爆缓存表，导致正常条目被挤出。交换机和网关一般配置 ARP 速率限制。

### 3. 抓不到 ARP 应答

可能原因：目标主机 IP 配置错误、防火墙丢弃 ARP（ARP 不该被过滤）、交换机端口隔离（private-vlan）阻断广播、VLAN 划分错误导致广播域不一致。

## 免费 ARP（Gratuitous ARP）

免费 ARP 是**主动广播**的 ARP 请求，目标 IP 填自己的 IP，作用有三个：

1. 通知链路上其他主机"我的 MAC 变了"，让它们刷新 ARP 缓存。
2. 检测 IP 冲突：若收到应答，说明网络上已有主机使用同一 IP。
3. 网关故障切换时立即通告（如 VRRP/HSRP 主备切换、双机热备切换后主动发免费 ARP，让终端马上把网关 MAC 更新为新的主机）。

## 路由器上的 ARP

### 多接口多子网

路由器每个接口属于不同子网，ARP 缓存按接口独立维护。`show arp` 中同一 IP 可能在不同 VLAN 中出现，转发时先查路由确定出接口，再在该接口对应的子网内解析下一跳 MAC。

### 代理 ARP（Proxy ARP）

路由器对"不属于本接口子网的目标 IP"代为应答 ARP，把自己 MAC 返回给请求者。常用于：

- 两个子网之间无路由设备时通过代理 ARP 实现互通。
- 主机只配置了 IP 和掩码、没有配网关的老式网络。

代理 ARP 降低了配置复杂度，但也增加了故障排查难度（ARP 应答与直觉不符），现代网络多用显式网关配置替代。

## 二层交换机的 ARP 无关性

二层交换机转发依据的是 MAC 地址表（CAM 表），不解析 IP，所以交换机**不处理也不终结 ARP**，只把 ARP 广播帧向同 VLAN 的所有端口泛洪。三层交换机和路由器才会参与 ARP 解析。

## 与 RARP / NDP 对比

| 协议 | 作用 | 适用场景 |
|------|------|----------|
| ARP | IP → MAC | IPv4 以太网 |
| RARP | MAC → IP | 早期无盘工作站启动获取 IP，已被 DHCP 取代 |
| NDP | IP(v6) → MAC | IPv6 邻居发现，功能更丰富（含地址自动配置、重复地址检测） |

## 小结

ARP 是 IPv4 以太网通信的必经之路，理解"同一子网解析目标、跨子网解析网关"这两个场景，配合缓存状态机，即可排查绝大多数 ARP 相关故障。
