# VRRP
虚拟路由冗余协议是一种容错协议，解决局域网中静态网关单点失效问题的一种冗余协议。

## VRRP 实现原理
局域网中，实现与外部网络的同行，会在每个主机上设置一个网关IP，或者在终端上配置一条默认路由，下一跳指向网关路由器。   
VRRP通过将一组路由设备联合组成一台虚拟路由设备的方式，将网络内主机的默认网关设置为该虚拟路由设备的IP地址。实现了互相隔离的物理设备在逻辑上的统一，使得终端设备在发送给逻辑网关IP地址的时候自动在多个物理网关接口之间选路。   

## VRRP的主备选举
运行VRRP协议的物理路由器之间会进行选举，最终选举出一个master，其余路由器全部都处于backup状态。   

## VRRP基本概念
VRRP在不改变组网的情况下，将多台设备组成一个虚拟路由器，通过配置虚拟路由器的uo地址为默认网关，实现了默认网关的备份。   

### VRRP状态机
1. Initialize状态
2. master状态
3. backup状态

## VRRP 报文与选举机制

VRRP 报文基于 IP 封装，协议号 112，组播地址 224.0.0.18，**主备之间不需要 BFD 等额外协议**。选举规则：

1. 优先比较**优先级**（默认 100，范围 1~254），数值大者成为 master。
2. 优先级相同则比较接口 IP，IP 大者成为 master。
3. master 周期发送 VRRP 通告（默认 1s），backup 在**3 倍通告时间**内未收到通告即抢占成为新 master。

VRRP 有两种运行方式：抢占式（默认，backup 优先级更高时抢占 master）和非抢占式（先到先得，常用于双机热备避免频繁切换）。

## VRRPv3

VRRPv3（RFC 5798）相对 VRRPv2 的主要变化：

| 对比项 | VRRPv2 | VRRPv3 |
|--------|--------|--------|
| 支持协议族 | 仅 IPv4 | IPv4 + IPv6 |
| 通告间隔 | 秒级 | 毫秒级（可配 100ms），切换更快 |
| 认证 | 支持简单认证 | 移除认证（原认证不安全），依赖 IPsec |
| 应用 | 传统园区网 | 数据中心、虚拟化网关场景 |

## VRRP 与 HSRP 对比

| 对比项 | VRRP | HSRP |
|--------|------|------|
| 标准 | IETF 标准（RFC 3768/5798），厂商通用 | Cisco 私有协议 |
| 虚拟 IP | 可等于某台真实设备接口 IP | 必须是独立虚拟 IP |
| 组播地址 | 224.0.0.18 | 224.0.0.2 |
| 协议号 | 112 | UDP 1985 |
| 主备角色 | Master/Backup | Active/Standby |
| 抢占 | 默认开启 | 默认关闭 |

## Track 机制

Track 用于**联动监控**，让 VRRP 感知接口/链路状态并自动调整优先级：

- 跟踪**上行接口**：WAN 口断开时，master 主动降低优先级，让 backup 接管虚拟 IP，流量切换到备用链路。
- 跟踪**路由**：监控某条关键路由是否存在，路由丢失即触发降级。
- 跟踪**BFD**：与 BFD 联动，毫秒级感知对端故障，比 VRRP 自身超时快得多。

配置示例：`vrrp group 1 track interface gigabitethernet1/0/1 reduced 30`，上行口 down 时优先级减 30，backup 即可抢占。

## 实际组网要点

- 双机热备（Active/Standby）：两台设备同一 VRRP 组，虚拟 IP 做网关，流量走 master，master 故障秒级切换。
- 负载均衡（Active/Active）：两个 VRRP 组互为 master，分别承担不同 VLAN 的网关流量，两台设备同时干活。
- 终端侧需配合**免费 ARP**：master 切换后立即发送免费 ARP，通知交换机刷新 MAC 表，否则流量仍指向旧设备。
