# TR-069 / TR-369（CPE 远程管理协议）

## 一、TR-069 协议概述

### 1.1 什么是 TR-069
TR-069（Technical Report 069），又称 **CWMP**（CPE WAN Management Protocol，CPE 广域网管理协议），由 Broadband Forum 制定。它用于运营商通过 ACS（Auto-Configuration Server，自动配置服务器）对家庭网关、路由器、机顶盒等 CPE 设备进行远程管理，是当前运营商接入设备管理的事实标准。

### 1.2 ACS 与 CPE 交互模型

| 角色 | 说明 |
|------|------|
| **ACS** | 运营商侧管理服务器，负责下发配置、升级固件、采集状态 |
| **CPE** | 用户侧设备（家庭网关 / 路由器 / 机顶盒），主动连接 ACS 发起会话 |

交互特点：
- **会话由 CPE 主动发起**，使用 HTTP over TCP，生产环境通常走 HTTPS（443 端口）。
- 每次会话以 CPE 发 `Inform` 开始，以 CPE 发 `Empty HTTP Response` 结束，一对请求/响应构成一个完整会话。
- 连接方向是 CPE → ACS，因此 CPE 处于 NAT 之后也能被远程管理。

典型会话时序：`CPE --Inform--> ACS --InformResponse--> CPE --RPC(Get/Set/Download)--> ACS --Response--> CPE --Empty Response--> 会话结束`

### 1.3 RPC 方法

| RPC | 方向 | 作用 |
|-----|------|------|
| `Inform` | CPE → ACS | 会话开始，上报设备标识、事件、参数变更 |
| `GetParameterValues` | ACS → CPE | 读取参数值 |
| `SetParameterValues` | ACS → CPE | 修改参数值（远程配置下发） |
| `Download` | ACS → CPE | 下载固件 / 配置文件 |
| `Upload` | ACS → CPE | 上传日志、诊断文件 |
| `Reboot` / `FactoryReset` | ACS → CPE | 重启 / 恢复出厂 |
| `ConnectionRequest` | ACS → CPE | 请求 CPE 主动发起新会话（外部触发） |

## 二、TR-069 核心机制

### 2.1 周期性 Inform
- CPE 按配置的周期（`PeriodicInformInterval`，默认如 86400 秒）定期向 ACS 发送 Inform。
- Inform 携带 **Event Codes** 事件码，常见有：
  - `0 BOOTSTRAP`：设备首次注册，需初始化配置
  - `1 BOOT`：设备启动
  - `2 PERIODIC`：周期性上报
  - `6 CONNECTION REQUEST`：响应 ACS 的外部触发
- 周期性 Inform 保证设备状态、配置版本与 ACS 持续同步。

### 2.2 Connection Request
问题：ACS 想主动控制 CPE，但 CPE 在 NAT 之后，TCP 连接无法从外网主动建立。

解决手段：

| 方式 | 说明 |
|------|------|
| **Connection Request（最常用）** | CPE 在 Inform 中上报 `ConnectionRequestURL`，ACS 用 HTTP 向该 URL 发送 Connection Request，CPE 收到后主动发起新会话 |
| **STUN / UDP 打洞** | CPE 通过 STUN 获取公网 IP:Port 映射，ACS 利用该映射向 CPE 发送 UDP 消息触发会话，适合防火墙受限场景 |
| **保持长连接** | 部分实现通过 WebSocket 等维持长连接，多用于 TR-369 场景 |

STUN 打洞流程：CPE 向 STUN 服务器请求 → 获得 NAT 映射的公网地址 → 上报给 ACS → ACS 直接向该地址发 UDP 触发消息 → CPE 建立新会话。

## 三、关键数据模型

### 3.1 数据模型的作用
TR-069 用"参数树"描述设备的全部能力与状态，RPC 操作的对象就是参数树上的节点。节点采用类似文件系统的层次化命名。

### 3.2 TR-098 / TR-181

| 规范 | 说明 |
|------|------|
| **TR-098（InternetGatewayDevice）** | 早期家庭网关数据模型，根节点为 `InternetGatewayDevice.` |
| **TR-181（Device Data Model）** | 新一代统一数据模型，根节点为 `Device.`，同时覆盖网关、机顶盒、IoT 等多种设备 |

数据模型演进方向是 TR-098 → TR-181，统一到 **`Device.` 前缀**。

### 3.3 常见节点示例

| 路径 | 含义 |
|------|------|
| `Device.DeviceInfo.SoftwareVersion` | 固件版本 |
| `Device.DeviceInfo.SerialNumber` | 设备序列号 |
| `Device.ManagementServer.URL` | ACS 地址 |
| `Device.WANDevice.1.WANConnectionDevice.1.WANIPConnection.1.ExternalIPAddress` | WAN 外网 IP |
| `Device.IP.Diagnostics.*` | Ping / TraceRoute 诊断结果 |

多实例对象用 `.N.` 表示，例如 `Device.WANDevice.1.` 代表第一个 WAN 设备。

## 四、OpenWrt 中 TR-069 实现

### 4.1 常见实现方案

| 实现 | 说明 |
|------|------|
| **easycwmp** | 开源 C 语言 CWMP Agent，OpenWrt 常用，支持 TR-069 与 TR-369（USP），与 UCI、ubus 深度集成 |
| **openwrt-tr069** | OpenWrt 早期开源 TR-069 实现（基于 netifd 之上），已较少维护 |
| **厂商私有 Agent** | 各路由器厂商自研的 CWMP 客户端，多为商业实现 |

### 4.2 easycwmp 与 OpenWrt 集成要点
- easycwmp 以守护进程运行，读取 UCI 配置 `/etc/config/easycwmp`。
- 数据模型通过 **插件机制** 对接系统：读 UCI、调用 ubus、执行 shell 命令。
- ACS 下发的 `SetParameterValues` 最终写入 UCI，并通过 procd/netifd 触发生效。
- 固件升级：`Download` RPC 下载镜像 → 校验 → 写入 mtd 分区 → 重启。

## 五、CPE 中 TR-069 典型用途

| 用途 | 机制 |
|------|------|
| **远程配置下发** | `SetParameterValues` 修改 UCI 配置并生效 |
| **固件升级** | `Download` 下载固件镜像，校验后刷写分区 |
| **性能监控** | Inform / `GetParameterValues` 周期性上报 CPU、内存、流量、信号强度 |
| **故障诊断** | 远程触发 Ping/TraceRoute（`Device.IP.Diagnostics.*`）、`Upload` 抓取日志 |
| **批量开局** | 首次上电触发 `BOOTSTRAP` 自动向 ACS 注册，实现零接触部署（ZTP） |

## 六、TR-369 / USP 演进

### 6.1 为什么需要 USP
TR-069 基于 HTTP 轮询 + XML，存在明显不足：
- 传输依赖 HTTP/XML/SOAP，消息开销大、效率低。
- 会话必须由 CPE 主动发起，实时性受限。
- 数据模型与传输方式耦合，扩展复杂。

### 6.2 USP 与 TR-069 对比

| 维度 | TR-069 (CWMP) | TR-369 (USP) |
|------|---------------|--------------|
| 全称 | CPE WAN Management Protocol | User Services Platform |
| 传输 | HTTP(S) / SOAP + XML | **MQTT / WebSocket / STOMP** |
| 消息格式 | XML | MessagePack / JSON |
| 端点角色 | CPE（被管）、ACS（管理） | **Agent**（设备侧）、**Controller**（管理侧） |
| 通信方向 | 基本 CPE → ACS | 双向可主动发起 |
| 控制器数量 | 单 ACS | 支持多 Controller |
| 通信场景 | 主要走广域网 | 广域网、局域网直连、MQTT Broker 云中转均可 |
| 数据模型 | TR-098 / TR-181 | 沿用 **TR-181（`Device.` 前缀）** |

### 6.3 USP 关键概念
- **Agent**：设备侧实体，对应 TR-069 的 CPE。
- **Controller**：管理侧实体，对应 ACS。
- **Endpoint ID**：全局唯一端点标识，用于设备与控制器互相认证。
- **Message / Record**：USP 消息（操作内容）与 Record（传输封装），支持加密与签名（如 OSCORE）。

### 6.4 OpenWrt 中的 USP 实践
- **obuspa**：Broadband Forum 官方开源的 USP Agent（C 语言），可编译运行于 OpenWrt。
- easycwmp 较新版本同时内置 CWMP 与 USP 支持。
- 传输选型：NAT 后设备常用 **MQTT**（经 Broker 中转）；局域网直连常用 **WebSocket / STOMP**。

## 七、总结

| 要点 | 结论 |
|------|------|
| TR-069 是当前主流 | 运营商家庭网关远程管理的实际标准，基于 HTTP + SOAP |
| TR-369 是演进方向 | 传输更灵活（MQTT/WebSocket/STOMP）、双向通信，适配 IoT 时代 |
| 数据模型一脉相承 | TR-098 已过渡到 TR-181，统一为 `Device.` 前缀 |
| OpenWrt 实践 | easycwmp（CWMP + USP）、obuspa（USP）是主要开源选择 |
