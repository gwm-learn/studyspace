# WiFi 相关概念

## 1. WiFi 频段与信道规划

### 1.1 2.4GHz 频段

频段范围 2.400~2.4835GHz，信道带宽 20MHz，信道间隔 5MHz。2.4GHz 传播好、穿墙能力强，但频段拥挤，干扰源多（蓝牙、微波炉、USB3.0）。

| 项目 | 说明 |
|------|------|
| 信道总数 | 中国 1~13，美国 1~11 |
| 不重叠信道 | 1、6、11（三个互不干扰，20MHz 下） |
| 建议 | 邻居 AP 尽量选 1/6/11 中不同信道，避免同频干扰 |
| 40MHz 绑定 | 只能绑相邻信道，如 1+5、6+10，空间有限，拥挤环境下反而更易冲突 |

### 1.2 5GHz 频段

频段范围 5.15~5.85GHz，信道编号间隔 4（36、40、44、48……），每信道 20MHz。

| UNII 子段 | 频段 | 信道 | 备注 |
|-----------|------|------|------|
| UNII-1 | 5.15~5.25GHz | 36/40/44/48 | 室内低功率 |
| UNII-2 | 5.25~5.35GHz | 52/56/60/64 | 需 DFS |
| UNII-2 Extended | 5.47~5.725GHz | 100~144 | 需 DFS，雷达共存 |
| UNII-3 | 5.725~5.85GHz | 149~165 | 免 DFS，多数家用首选 |

5GHz 干扰少、信道多，适合高带宽场景，但穿墙衰减比 2.4GHz 严重。DFS 信道需要监听雷达信号，一旦检测到雷达要主动让出信道（切换时间不确定），家用场景常避开。

### 1.3 6GHz 频段（WiFi 6E / WiFi 7）

频段 5.925~7.125GHz，从信道 1 到 233（20MHz 步进），无线宽带更高，全部信道免 DFS。6GHz 是 WiFi 6E（802.11ax）和 WiFi 7（802.11be）的专属频段，强制要求 WPA3 加密（SAE + PMF），不允许开放网络。中国尚未开放 6GHz，目前主要在美国、韩国等地使用。

### 1.4 信道绑定：HT20/40/80/160

绑定（bonding）把多个相邻 20MHz 信道合成一个更宽的通道，提高单链路吞吐，但也占用更多频谱、增大邻频干扰。

| 模式 | 带宽 | 所属协议 | 典型使用 |
|------|------|----------|----------|
| HT20/HT40 | 20/40MHz | 802.11n | 2.4GHz 建议只用 HT20 |
| VHT20/40/80/160 | 最高 160MHz | 802.11ac | 5GHz 常用 VHT80 |
| HE20/40/80/160 | 最高 160MHz | 802.11ax | WiFi 6 常规 VHT80/HE160 |
| EHT 最高 320MHz | 320MHz | 802.11be | WiFi 7 专属，需 6GHz |

主信道（primary channel）是控制信道，始终 20MHz，负责 beacon、管理帧与低速率控制；宽通道只在数据帧时启用。带宽越宽吞吐越高，但可用信道数越少（5GHz 下 80MHz 只有 3~4 个不重叠宽通道）。

## 2. WiFi 加密方式演进

| 代次 | 出现时间 | 加密/认证机制 | 密钥长度 | 状态 |
|------|----------|--------------|----------|------|
| WEP | 1997 | RC4 流加密 | 64/128 位 | 已废弃，数分钟内可破解 |
| WPA | 2003 | TKIP（RC4 + MIC + 临时密钥） | 128 位 | 过渡方案，不推荐 |
| WPA2 | 2004 | CCMP/AES（802.11i 标准） | 128 位 | 长期主流，有 KRACK 漏洞 |
| WPA3 | 2018 | SAE 握手、PMF 强制、GCMP-256 | 192 位（企业级） | 当前推荐 |

演进主线：**密钥可被暴力推算 → 每帧动态换钥 → AES 硬件加密 → 抗离线字典攻击**。

- WEP 的 RC4 密钥固定且太短，抓包即可算出密钥，毫无安全性。
- WPA 的 TKIP 仍是 RC4，只是加了每包密钥与消息完整性校验（MIC），作为 WEP 到 WPA2 之间的过渡。
- WPA2 用 AES-CCMP，是真正意义的现代加密；2017 年 KRACK 攻击利用四次握手中的密钥重装漏洞可解密流量，需要补丁修复。
- WPA3 用 SAE（Equal 认证，即 Dragonfly 协议）替换 WPA2 的 PSK 四次握手，即使密码简单也无法离线穷举；同时强制开启 PMF（802.11w 管理帧保护），防止 deauth 攻击。
- 开放网络可用 OWE（Opportunistic Wireless Encryption，802.11s 之外的单播加密）实现无密码但加密的公共热点。

## 3. 802.11 协议族对比

| 标准 | 商用名 | 年份 | 频段 | 最大速率 | 信道带宽 | 调制 | 关键特性 |
|------|--------|------|------|----------|----------|------|----------|
| 802.11a | - | 1999 | 5GHz | 54Mbps | 20MHz | OFDM | 首个 OFDM 方案 |
| 802.11b | - | 1999 | 2.4GHz | 11Mbps | 20MHz | DSSS/CCK | 普及功臣，速率低 |
| 802.11g | - | 2003 | 2.4GHz | 54Mbps | 20MHz | OFDM | 兼容 b |
| 802.11n | WiFi 4 | 2009 | 2.4/5GHz | 600Mbps | 20/40MHz | OFDM | MIMO、帧聚合 |
| 802.11ac | WiFi 5 | 2013 | 5GHz | 6.9Gbps | 最高 160MHz | OFDM | 下行 MU-MIMO、256-QAM |
| 802.11ax | WiFi 6 | 2019 | 2.4/5GHz | 9.6Gbps | 最高 160MHz | OFDMA | 上下行 MU-MIMO、1024-QAM、TWT |
| 802.11be | WiFi 7 | 2024 | 2.4/5/6GHz | 约 46Gbps | 最高 320MHz | OFDMA | 多链路 MLO、4096-QAM |

## 4. WiFi 漫游技术

家用 AP 只有一个时不存在漫游；多 AP 覆盖同一 SSID 时，终端需要在 AP 间切换，切换质量决定体验。漫游分两步：**发现目标 AP（扫描）** 和 **重新认证（握手）**。802.11k/v/r 分别优化这两步：

| 标准 | 名称 | 作用 | 说明 |
|------|------|------|------|
| 802.11k | 邻居报告 | 加速发现 | 客户端向当前 AP 请求邻居 AP 列表，按列表定向扫描，避免全信道盲扫 |
| 802.11v | BSS Transition | 主动引导切换 | AP 携带各邻居的负载、信号信息，建议客户端切换到更优 BSS；支持 BSS 最大空闲时间踢下线 |
| 802.11r | Fast Transition（FT） | 加速认证 | 预分发 PMK，把 802.1X/PSK 的四次握手压缩为两次（FT 认证），切换时延降到几十毫秒 |

三者的关系：**k 提供信息，v 做决策，r 加速执行**。OpenWrt 的 wpad-full 中开启 `option ieee80211k/v/r '1'` 即可同时启用，配 `mobility_domain` 与 `ft_psk_generate_local` 实现 PSK 快速漫游。另外 802.11w（PMF）强制管理帧加密，是 WPA3 的必选项，与漫游安全性相关。

## 5. MIMO、MU-MIMO 与 OFDMA

| 技术 | 原理 | 收益 | 代表协议 |
|------|------|------|----------|
| MIMO | 多根天线同时收发多个空间流 | 提升单用户峰值速率 | 802.11n 起 |
| MU-MIMO | 同一时刻把不同空间流分给多个用户 | 提升多用户并发吞吐 | ac 仅下行 4 用户，ax 上下行均可 |
| OFDMA | 把信道切成资源单元（RU），多用户并行占用不同子载波 | 大幅降低小包场景的争用开销 | 802.11ax/be 核心特性 |

- MIMO 用多天线做空间复用，速率随空间流数倍增（如 2x2 比 1x1 快一倍），但终端也要同样多的天线才有效。
- MU-MIMO 弥补了 OFDM 时代"同一时刻只服务一个用户"的浪费。WiFi 5 只支持下行 4 个用户同时收，WiFi 6 的上下行 MU-MIMO 让多用户可同时收发包。
- OFDMA 把 20MHz 分成最多 9 个 RU（资源单元），多个终端各占一个 RU 同时传输。对智能家居、IoT 这类海量小数据包场景提升最明显，不必再一个个排队争信道。
- WiFi 6 的组合拳是 **OFDMA（多用户频分）+ MU-MIMO（多用户空间）+ 1024-QAM（更高调制）+ TWT（终端节能调度）**；WiFi 7 再加 320MHz、MLO 多链路并发与 4096-QAM。

## 6. OpenWrt 中 WiFi 配置要点

WiFi 配置集中在 `/etc/config/wireless`，由 netifd + wpad（hostapd/wpa_supplicant）+ iw 协作落地。结构是"物理设备 + 逻辑接口"两层。

`config wifi-device`（物理 radio，对应内核 wiphy）：

| 选项 | 示例 | 说明 |
|------|------|------|
| `option type` | `mac80211` | 驱动类型，SoftMAC 走 mac80211 |
| `option phy` | `phy0` | 绑定内核 wiphy |
| `option band` | `2.4GHz` / `5GHz` | 频段 |
| `option channel` | `auto` / `1` / `36` | 信道，auto 让驱动自选最空闲信道 |
| `option htmode` | `HT20` / `VHT80` / `HE80` / `HE160` | 协议模式与带宽 |
| `option country` | `CN` | 国家码，决定可用信道与最大发射功率（依赖 regdb） |
| `option txpower` | `20` | 发射功率（dBm） |
| `option disabled` | `0` | 0 启用，1 禁用 |

`config wifi-iface`（逻辑接口，对应 wireless_dev）：

| 选项 | 示例 | 说明 |
|------|------|------|
| `option device` | `radio0` | 所属物理设备 |
| `option network` | `lan` | 桥接的 logical 接口，数据面由 netifd 处理 |
| `option mode` | `ap` / `sta` / `mesh` | 工作模式 |
| `option ssid` | `mywifi` | 网络名称 |
| `option encryption` | `psk2` / `sae` / `psk-mixed` / `none` | 加密方式；sae 即 WPA3 |
| `option key` | `secret` | 预共享密钥（sae/psk 用） |
| `option ieee80211k` | `1` | 开启 802.11k 邻居报告 |
| `option ieee80211v` | `1` | 开启 802.11v BSS 切换 |
| `option ieee80211r` | `1` | 开启 802.11r 快速漫游 |
| `option mobility_domain` | `a1b2` | FT 移动域标识，同一域内 AP 可快速切换 |
| `option ft_psk_generate_local` | `1` | PSK 场景本地生成 PMK-R0/R1，无需 RADIUS |

配置要点：

- 加密选择优先 `sae`（WPA3），老设备兼容用 `psk-mixed`（WPA2/WPA3 共存）。
- 2.4GHz 建议 `HT20`，5GHz 可用 `HE80` 及以上；带宽越大吞吐越高，但相邻 AP 共享频谱，人多场景适可而止。
- 漫游三件套（k/v/r）依赖 wpad 完整版，OpenWrt 默认 `wpad-basic` 功能不全，需换装 `wpad-full` 或 `wpad-mbedtls`。
- `wifi detect > /etc/config/wireless` 可重新生成默认配置；修改后 `wifi reload` 让 netifd 重新下发配置，`wifi status` 查看 radio 与接口状态。
