# cfg80211 详解

## 1. cfg80211 在 Linux WiFi 栈中的位置

cfg80211 是 Linux 内核的 **WiFi 配置管理层**，位于用户空间与驱动之间，为上层提供统一、与硬件无关的配置接口。整个 WiFi 协议栈自顶向下分层如下：

```
用户空间     wpa_supplicant / hostapd / iw / netifd
               │ netlink 消息
内核层       nl80211（通用 netlink 协议族）
               │ 解析命令、分发处理
           cfg80211（net/wireless/，配置与状态管理核心）
               │ 调用驱动回调
           mac80211（net/mac80211/，SoftMAC 的 MAC/MLME 软件实现）
               │ 驱动 ops
           具体驱动（ath9k / mt76 / iwlwifi 等 SoftMAC 驱动）
           ─────────────────────────────────────────────
           FullMAC 驱动（brcmfmac / ath10k 等）：固件实现 MAC，直接对接 cfg80211
```

| 层 | 位置 | 职责 |
|----|------|------|
| 用户空间 | wpa_supplicant、hostapd、iw、OpenWrt netifd | 发起扫描、连接、配置 AP 等管理动作 |
| nl80211 | 内核通用 netlink 族 | 用户空间与内核的通信通道，承载配置命令与事件 |
| cfg80211 | net/wireless/，头文件 include/net/cfg80211.h | 设备注册、接口管理、扫描/连接等配置管理，隐藏驱动差异 |
| mac80211 | net/mac80211/ | SoftMAC 驱动的 MAC 层软件实现（MLME、帧收发） |
| 驱动 | drivers/net/wireless/ | 操作具体无线硬件 |

要点：
- 对用户空间而言，cfg80211 屏蔽了芯片差异，wpa_supplicant 不必区分具体驱动。
- SoftMAC 驱动（如 ath9k、mt76）依赖 mac80211 完成 MAC/MLME；FullMAC 驱动（如 brcmfmac、ath10k）的 MAC 在固件里，直接使用 cfg80211，不经过 mac80211。
- cfg80211 本身**不收发数据帧**，只做配置与状态管理，数据面由驱动完成。

## 2. cfg80211 核心职责

cfg80211 是"策略 + 回调分发"层：接收上层请求，校验合法性，再回调到驱动去执行，并把结果以事件形式回报上层。

| 职责 | 说明 |
|------|------|
| 无线设备注册 | 驱动用 `wiphy_new()` 创建 `struct wiphy`，`wiphy_register()` 注册到内核，cfg80211 统一管理设备列表 |
| 接口管理 | 创建、删除、切换无线接口及其类型（STA、AP、monitor、P2P 等） |
| 扫描 | 触发扫描、管理扫描流程、上报扫描结果（BSS 列表） |
| 连接管理 | STA 模式下的 connect / disconnect，建立与拆除链路 |
| AP 管理 | 启动/停止 AP、管理 beacon、上报 STA 的关联与去关联 |
| 电源与射频 | 省电（PS）、动态省电、DFS、频谱管制（regulatory，依赖 regdb 数据库） |
| 事件上报 | 把扫描完成、连接成功/断开、漫游等事件推送给用户空间监听者 |

## 3. 关键数据结构

| 结构体 | 含义 | 关键成员/关联 |
|--------|------|--------------|
| `struct wiphy` | **物理无线设备**，一个无线网卡对应一个 wiphy | `wiphy_new()` 创建；含支持的频段 `bands[]`、能力位 `features`、`regulatory` 信息；可附带驱动私有数据 `priv` |
| `struct wireless_dev`（wdev） | **无线接口**，物理设备上的一个逻辑接口（如 wlan0、radio0） | 通过 `wdev->wiphy` 指向所属物理设备；含接口类型 `iftype`、当前状态（关联的 BSS 等） |
| `struct cfg80211_ops` | 驱动向 cfg80211 注册的回调集合 | `add_virtual_intf`、`del_virtual_intf`、`scan`、`connect`、`disconnect`、`start_ap`、`stop_ap` 等 |

关联关系：**一个 `wiphy` 可以有多个 `wireless_dev`**，例如一个物理 radio 上同时建 STA 与 monitor 两个接口。驱动填充 `cfg80211_ops`，cfg80211 通过它把上层请求转交到具体硬件。

## 4. nl80211 与 cfg80211 的关系

nl80211 是 cfg80211 之上的**通用 netlink 协议族**，二者共同构成内核侧 WiFi 管理通道：

- 用户空间通过 `NETLINK_GENERIC` 发送 nl80211 命令（如 `NL80211_CMD_SCAN`、`NL80211_CMD_CONNECT`）。
- 内核侧由 cfg80211 注册的 nl80211 处理函数解析命令，校验后调用驱动注册的 `cfg80211_ops` 回调。
- 硬件/驱动状态变化时，cfg80211 通过 nl80211 向用户空间发送多播事件（如扫描完成、断连）。

```
iw / wpa_supplicant ──nl80211 命令──► cfg80211 ──ops 回调──► 驱动/固件
iw / wpa_supplicant ◄──nl80211 事件── cfg80211 ◄──状态变化── 驱动/固件
```

即：**nl80211 是"壳"（netlink 协议），cfg80211 是"核"（策略与管理）**。内核侧源码上 nl80211 是 `net/wireless/nl80211.c`，它属于 cfg80211 子系统的一部分。

## 5. OpenWrt 中的 cfg80211

OpenWrt 的用户空间无线管理通过 `wpad`（wpa_supplicant + hostapd）、`iw`、`netifd` 协作完成，最终都转化为 nl80211 命令到达 cfg80211。

`/etc/config/wireless` 的典型结构与映射关系：

| wireless 配置项 | 含义 | 落到 cfg80211 的动作 |
|-----------------|------|---------------------|
| `config wifi-device 'radio0'` | 定义一个物理无线设备 | 对应一个 `wiphy`（通过 `option phy 'phy0'` 绑定） |
| `option channel '36'` | 工作信道 | 驱动 set channel（扫描/配置信道） |
| `option htmode 'HE80'` | 802.11 模式与带宽 | 能力协商与信道带宽配置 |
| `option country 'CN'` | 国家码 | 触发 regulatory 设置，cfg80211 查询 regdb 校准功率 |
| `config wifi-iface` | 定义一个无线接口 | 对应一个 `wireless_dev`，创建接口时调用 add_virtual_intf |
| `option mode 'sta'` | 接口工作模式 | 决定接口类型（STA/AP/monitor），涉及 iftype 切换 |
| `option ssid` / `option encryption` | SSID 与加密方式 | 供 wpa_supplicant/hostapd 构造 connect / start_ap 流程 |
| `option network 'lan'` | 桥接的 logical 接口 | 接口创建后由 netifd 桥接，数据面不经过 cfg80211 |

整体流程：`netifd` 解析 `/etc/config/wireless` 后调用 `wifi detect` 生成/修正配置，再通过 `iw` 或 `wpa_supplicant`/`hostapd` 下发 nl80211 命令，最终由 cfg80211 回调驱动完成扫描、关联、AP 启动等动作。`radio` 与接口的生命周期（up/down）也由 netifd 通过 nl80211 的 `set_wiphy`、接口增删命令管理。
