# nl80211（WiFi 内核配置接口）

# 概述

nl80211 是**用户空间与内核 cfg80211 子系统之间**的 netlink 通信接口，负责 WiFi 相关的配置、查询与事件上报。用户空间的 WiFi 管理工具（iw、wpa_supplicant、hostapd）通过它向内核下发命令，内核把扫描结果、连接事件等主动推送给用户空间。

在 nl80211 出现之前，Linux 使用 **Wireless Extensions（WEXT）**，基于 ioctl 实现，接口僵硬、难以扩展，且把大量协议细节暴露给用户空间。nl80211 采用 netlink 的通用机制，命令和属性可任意扩展，后来完全取代了 WEXT。

整个链路为：用户空间（iw/hostapd/wpa_supplicant）→ nl80211 → 内核 cfg80211 → mac80211/厂商驱动。内核侧，`net/wireless/nl80211.c` 把收到的 nl80211 消息解析为对 cfg80211 各接口的调用；驱动通过注册 `cfg80211_ops` 结构体实现具体硬件操作。

# Generic Netlink 家族机制

nl80211 构建在 **Generic Netlink（genl）** 之上。普通 netlink 靠协议号区分用途（如 NETLINK_ROUTE、NETLINK_NETFILTER），扩展性差；Generic Netlink 增加了一层"家族"（family）抽象，同一个 `NETLINK_GENERIC`（协议号 16）下可以注册多个家族，各家族再细分命令与属性。

- 每个家族有名字和唯一 ID，家族 ID 由内核动态分配，用户空间通过 `CTRL_CMD_GETFAMILY` 查询，nl80211 的家族名固定为 `nl80211`。
- 家族内定义**命令**（command）和**属性**（attribute），消息是"命令 + 若干属性"的结构。
- 内核在启动时注册 `nl80211` 家族，并申请 `NL80211_MULTICAST_GROUP_*` 多播组，用于向用户空间主动推送事件。

常用多播组：

| 多播组 | 用途 |
|--------|------|
| SCAN | 扫描结果通知 |
| MLME | 连接/断开等管理帧事件 |
| CONFIG | 接口配置变化 |
| REG | 无线频段管制域变化 |

# nl80211 消息结构：命令与属性

一条 nl80211 消息由三部分组成：

1. **家族头**：由 Generic Netlink 框架填充，标识家族 ID。
2. **命令**：`NL80211_CMD_*` 枚举，如 `NL80211_CMD_TRIGGER_SCAN`、`NL80211_CMD_CONNECT`，表示"要做什么"。
3. **属性**：`NL80211_ATTR_*` 嵌套结构，携带命令的参数，如接口索引、SSID、BSSID、信道等。

属性支持**嵌套**，例如扫描命令里的 `NL80211_ATTR_SCAN_SSIDS` 和 `NL80211_ATTR_SCAN_FREQUENCIES` 都是嵌套属性，里面再包一层属性列表。触发扫描的消息结构示意：命令 `NL80211_CMD_TRIGGER_SCAN`，属性 `NL80211_ATTR_IFINDEX=5`、`NL80211_ATTR_WIPHY=0`、`NL80211_ATTR_SCAN_SSIDS`（嵌套）。

常用命令：

| 命令 | 作用 |
|------|------|
| `GET_WIPHY` | 查询物理无线设备（phy）能力 |
| `GET_INTERFACE` / `NEW_INTERFACE` / `DEL_INTERFACE` | 查询、创建、删除虚拟接口 |
| `SET_INTERFACE` | 设置接口类型（station、ap、monitor 等） |
| `TRIGGER_SCAN` / `GET_SCAN` | 触发扫描 / 获取扫描结果 |
| `CONNECT` / `DISCONNECT` | STA 模式连接 / 断开 AP |
| `START_AP` / `STOP_AP` | AP 模式启动 / 停止 |
| `GET_STATION` | 查询已关联站点信息 |

# 常用 nl80211 命令

## 扫描（trigger scan / get scan）

扫描是异步过程，分两步：

1. 下发 `NL80211_CMD_TRIGGER_SCAN`，携带接口索引和可选的信道/SSID 过滤条件，内核开始扫描并立即返回。
2. 扫描完成后，内核向 SCAN 多播组推送 `NL80211_CMD_NEW_SCAN_RESULTS` 事件；用户空间再发 `NL80211_CMD_GET_SCAN` 带 `NLM_F_DUMP` 获取完整的 BSS 列表（每个 BSS 是一组 `NL80211_BSS_*` 属性：BSSID、SSID、信号强度、频点、加密方式等）。

## 连接（connect）

STA 模式连接由 `NL80211_CMD_CONNECT` 完成，属性包括：

- `NL80211_ATTR_SSID`：目标网络名
- `NL80211_ATTR_BSSID`：可选的指定 BSSID
- `NL80211_ATTR_AUTH_TYPE`：认证方式（开放、共享密钥、SAE 等）
- `NL80211_ATTR_AKM_SUITES` / `NL80211_ATTR_CIPHER_SUITES`：密钥管理与加密套件

连接结果通过 MLME 多播组推送：成功发 `NL80211_CMD_CONNECT` 事件（携带 BSSID），失败发 `NL80211_CMD_DEAUTHENTICATE` 或 `NL80211_CMD_DISCONNECT` 事件。

## 获取接口信息

`NL80211_CMD_GET_INTERFACE` 返回接口的类型、MAC 地址、所在 phy、工作频点、关联的 AP（station 模式）等。iw 的 `iw dev`、`iw dev wlan0 info` 底层调用的就是它。

# iw 命令行工具

iw 是 nl80211 官方的命令行前端，作者与 nl80211 相同（Johannes Berg），基于 **libnl** 封装 netlink 收发。它替代了旧 WEXT 时代的 `iwconfig`/`iwlist`。

常用示例：

```
iw dev                                   # 列出所有无线接口及状态
iw phy                                   # 查看物理设备能力（频段、HT/VHT/HE）
iw dev wlan0 info                        # 查看 wlan0 详细信息
iw dev wlan0 scan                        # 扫描并列出周边 AP
iw dev wlan0 connect MyWiFi              # 连接开放网络
iw dev wlan0 connect MyWiFi key 0:12345  # 连接 WEP 网络
iw dev wlan0 station dump                # 查看已关联站点
iw dev wlan0 set type monitor            # 切换为监听模式
iw phy phy0 interface add mon0 type monitor  # 动态创建监听接口
```

iw 命令与 nl80211 命令的对应关系清晰：`iw dev wlan0 scan` 即 `TRIGGER_SCAN` + `GET_SCAN`，`iw dev wlan0 connect` 即 `CONNECT`。它是验证 nl80211 通路是否正常的第一工具。

# hostapd / wpa_supplicant 如何通过 nl80211 驱动 WiFi

hostapd 与 wpa_supplicant 同出自 wpa_supplicant 项目，内部都有一层**驱动抽象**（`wpa_driver_ops`），通过 `-D` 参数选择具体驱动后端，常用 `-D nl80211`。

- **wpa_supplicant**：STA 客户端，负责扫描、选网、密钥协商（WPA2/WPA3、802.1X）。它用 nl80211 下发 `TRIGGER_SCAN`、`CONNECT`，并订阅 MLME 多播组接收断开/漫游事件；EAPOL 等管理帧经内核转发交给它处理。
- **hostapd**：AP 服务端，负责 beacon、关联、密钥分发。启动流程是用 nl80211 创建或切换接口为 `NL80211_IFTYPE_AP`，下发 `NL80211_CMD_SET_WIPHY` 设置频段与信道，最后 `NL80211_CMD_START_AP` 开启 AP；客户端的连接请求通过 MLME 事件上抛给 hostapd 完成认证与四次握手。

```
wpa_supplicant -D nl80211 -i wlan0 -c wpa_supplicant.conf
hostapd -B /etc/hostapd.conf     # 默认使用 nl80211 驱动
```

在 OpenWrt 上，`wpad`（含 hostapd 与 wpa_supplicant 的合并二进制）就是用 `-D nl80211` 驱动 WiFi 的。netifd 启动无线接口时，通过 `wifi` 脚本读取 UCI 的 `/etc/config/wireless`，为每个 radio 拉起对应的 wpad 进程，UCI 配置转换成 hostapd/wpa_supplicant 的配置文件（/var/run/hostapd 下），进程再经由 nl80211 把配置落到内核。因此"UCI 配置到实际生效"的完整链条是：`/etc/config/wireless` → netifd/wifi 脚本 → hostapd/wpa_supplicant → nl80211 → cfg80211 → 驱动。

# 调试与排障

- `iw dev`、`iw dev wlan0 scan`：先确认 nl80211 通路与射频环境正常。
- `logread | grep hostapd`：看 hostapd 启动与关联日志。
- `cat /sys/kernel/debug/ieee80211/phy0/`：内核 mac80211 调试信息，需开启 CONFIG_MAC80211_DEBUGFS；也可用 strace 直接观察 nl80211 消息收发。

# 小结

- nl80211 是 Linux WiFi 事实上的标准控制接口，建立在 Generic Netlink 之上，用户空间与 cfg80211 通过它通信。
- 消息结构为"家族 + 命令 + 属性"，事件通过多播组异步推送。
- iw 是 nl80211 的命令行前端；wpa_supplicant/hostapd 通过 `-D nl80211` 驱动 WiFi，OpenWrt 的无线配置经由它们落到内核。
- 排障顺序：`iw` 验证通路 → hostapd 日志看服务 → 内核 debugfs 看驱动。
