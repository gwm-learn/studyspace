# 桥接（Bridge）

## 一、概述

### 1.1 什么是桥接？
桥接（Bridge）是一种工作在数据链路层（OSI 第二层）的网络设备，用于连接两个或多个网段，并在它们之间转发以太网帧。桥接根据 MAC 地址进行转发决策，所有连接到同一桥接的设备处于**同一个广播域**，属于同一 IP 子网。

### 1.2 在 OpenWrt 中的作用
OpenWrt 利用 Linux 内核的桥接模块实现以下功能：
- **有线与无线融合**：将多个有线 LAN 端口和无线 Wi‑Fi 接口桥接在一起，形成统一的局域网（如默认的 `br-lan`）。
- **网络隔离**：创建独立的桥接（如 Guest 网络），实现二层隔离。
- **虚拟化支持**：为 KVM/LXC 容器提供虚拟网络桥接。
- **网络扩展**：通过桥接连接不同物理接口，扩展局域网规模。

### 1.3 桥接 vs 路由
| 特性 | 桥接（Bridge） | 路由（Router） |
|------|----------------|----------------|
| 工作层级 | 数据链路层（L2） | 网络层（L3） |
| 寻址依据 | MAC 地址 | IP 地址 |
| 广播域 | 同一广播域 | 不同广播域 |
| 隔离能力 | 无（所有接口在同一广播域） | 有（每个接口属于不同子网） |
| 典型应用 | 扩展局域网，连接有线与无线 | 连接不同子网，实现网络间通信 |

### 1.4 OpenWrt 桥接的默认配置
全新安装的 OpenWrt 通常已配置一个名为 `br-lan` 的桥接，其成员包括：
- 有线 LAN 端口（如 `eth0.1`，对应 VLAN 1）
- 无线接口（如 `wlan0`，如果已启用）

该桥接的 IP 地址为 `192.168.1.1`，充当 LAN 的网关和 DHCP 服务器。

## 二、Linux 内核桥接模块

### 2.1 内核模块
Linux 内核通过 `bridge` 模块实现桥接功能，该模块提供以下核心能力：
- **MAC 地址学习**：自动学习源 MAC 地址与端口的映射，构建转发数据库（FDB）。
- **帧转发**：根据 FDB 将帧转发到正确的端口，未知目的地址则广播。
- **生成树协议（STP）**：防止网络环路。
- **VLAN 过滤**：支持 VLAN-aware 桥接（每个端口可配置允许的 VLAN）。
- **多播侦听（IGMP snooping）**：优化多播流量转发。

### 2.2 相关内核参数
桥接行为可通过 `/sys/class/net/<brname>/bridge/` 下的文件进行调优：
- `stp_state`：STP 开关（0/1）
- `forward_delay`：转发延迟（秒）
- `hello_time`：Hello 报文间隔（秒）
- `max_age`：最大老化时间（秒）
- `ageing_time`：MAC 地址老化时间（秒）
- `multicast_snooping`：IGMP snooping 开关

通过 `sysctl` 调整全局参数：
```bash
sysctl -w net.bridge.bridge-nf-call-iptables=0   # 禁止桥接流量经过 iptables
```

### 2.3 内核与用户空间的交互
桥接配置通过 **netlink** 接口（`rtnetlink`）传递，用户空间工具（如 `ip`、`brctl`）通过 netlink 与内核通信。OpenWrt 的 `netifd` 也通过 netlink 监听桥接事件并下发配置。

## 三、OpenWrt 桥接配置

### 3.1 UCI 配置结构
桥接在 `/etc/config/network` 中通过 `config interface` 节定义，关键选项如下：

```uci
config interface 'lan'
        option proto 'static'
        option ipaddr '192.168.1.1'
        option netmask '255.255.255.0'
        option type 'bridge'                 # 标识该接口为桥接
        option ifname 'eth0.1 wlan0'         # 成员接口列表，以空格分隔
        option stp '0'                       # 是否启用 STP
        option ageing_time '300'             # MAC 地址老化时间（秒）
        option igmp_snooping '0'             # IGMP 侦听（可选）
```

#### 选项详解
- `type`：必须设置为 `bridge`，表示该接口为桥接。
- `ifname`：成员接口列表，多个接口用空格分开。接口可以是物理接口（`eth0`）、VLAN 接口（`eth0.1`）或虚拟接口（`wlan0`）。
- `stp`：生成树协议，`0` 表示禁用（默认），`1` 表示启用。在简单拓扑中可禁用，若网络存在环路则应启用。
- `ageing_time`：MAC 地址在转发数据库中的存活时间，超时后条目被删除。默认 300 秒。
- `igmp_snooping`：IGMP 侦听，可减少组播流量，默认禁用。
- `macaddr`：可选，手动设置桥接接口的 MAC 地址。

### 3.2 通过 netifd 管理桥接
netifd 将桥接视为一种**设备类型**（`type='bridge'`）。当配置中定义了一个 `type='bridge'` 的接口时，netifd 会执行以下操作：
1. 创建桥接设备（如 `br-lan`）。
2. 将 `ifname` 中列出的接口加入桥接。
3. 设置桥接参数（STP、老化时间等）。
4. 启动桥接接口并配置 IP 地址。

桥接设备的状态可通过 ubus 查询：
```bash
ubus call network.device status '{ "name": "br-lan" }'
```

### 3.3 配置示例

#### 3.3.1 将 Wi‑Fi 接口加入现有 LAN 桥接
```bash
uci set network.lan.type='bridge'
uci set network.lan.ifname='eth0.1 wlan0'
uci commit network
uci reload network
```

#### 3.3.2 创建新的 Guest 桥接
```bash
# 创建桥接接口
uci set network.guest=interface
uci set network.guest.proto='static'
uci set network.guest.ipaddr='192.168.3.1'
uci set network.guest.netmask='255.255.255.0'
uci set network.guest.type='bridge'
uci set network.guest.ifname='eth0.3 wlan1'

# 配置 DHCP
uci set dhcp.guest=dhcp
uci set dhcp.guest.interface='guest'
uci set dhcp.guest.start='100'
uci set dhcp.guest.limit='150'
uci set dhcp.guest.leasetime='12h'

# 提交并生效
uci commit network
uci commit dhcp
uci reload network
/etc/init.d/dnsmasq restart
```

#### 3.3.3 调整桥接参数
```bash
uci set network.lan.stp='1'
uci set network.lan.ageing_time='600'
uci commit network
uci reload network
```

## 四、桥接管理命令

### 4.1 brctl（传统工具）
`brctl` 是传统的桥接管理工具，功能简单，逐渐被 `ip` 命令取代。

```bash
# 显示所有桥接
brctl show

# 创建桥接
brctl addbr br-test

# 删除桥接
brctl delbr br-test

# 添加接口到桥接
brctl addif br-test eth0

# 从桥接移除接口
brctl delif br-test eth0

# 设置 STP
brctl stp br-test on
```

### 4.2 ip 命令（推荐）
`ip` 命令功能更强大，是当前管理桥接的首选工具。

```bash
# 创建桥接
ip link add name br-test type bridge

# 删除桥接
ip link del dev br-test

# 将接口加入桥接
ip link set dev eth0 master br-test

# 将接口从桥接移除
ip link set dev eth0 nomaster

# 设置桥接参数
ip link set dev br-test type bridge stp_state 1 ageing_time 600

# 显示桥接信息
ip link show type bridge
ip -d link show br-test
```

### 4.3 bridge 命令（高级管理）
`bridge` 命令提供更细致的桥接控制，如查看 FDB、VLAN 过滤等。

```bash
# 显示桥接详细信息
bridge link show

# 显示转发数据库（FDB）
bridge fdb show

# 显示 VLAN 过滤信息
bridge vlan show

# 添加静态 MAC 地址
bridge fdb add 00:11:22:33:44:55 dev eth0 master static
```

## 五、高级功能

### 5.1 生成树协议（STP）
STP 用于防止网络环路，避免广播风暴。OpenWrt 默认关闭 STP，在存在环路的拓扑中应启用。

启用 STP：
```bash
uci set network.lan.stp='1'
uci reload network
```

查看 STP 状态：
```bash
brctl showstp br-lan
```

### 5.2 VLAN 过滤（VLAN-aware Bridge）
Linux 桥接支持 VLAN 过滤，允许每个端口配置允许的 VLAN。这在需要基于 VLAN 进行隔离的场景中非常有用。

配置示例（通过 `bridge` 命令）：
```bash
# 允许 VLAN 10 和 20 通过
bridge vlan add vid 10 dev eth0
bridge vlan add vid 20 dev eth0

# 设置端口为 trunk（允许所有 VLAN）
bridge vlan add vid 1-4094 dev eth0

# 设置端口为 access（仅允许 VLAN 10）
bridge vlan add vid 10 dev eth0 pvid untagged
```

OpenWrt 中可通过 `switch` 配置实现硬件 VLAN 过滤，软件桥接的 VLAN 过滤需结合 `bridge` 命令手动配置。

### 5.3 IGMP Snooping
IGMP Snooping 可减少组播流量，只将组播数据转发给感兴趣的端口。OpenWrt 默认关闭，可在桥接配置中启用：

```uci
option igmp_snooping '1'
```

内核需启用 `CONFIG_BRIDGE_IGMP_SNOOPING` 编译选项。

### 5.4 多播转发（Multicast Forwarding）
对于 IPv4 组播，可启用 `multicast_querier` 和 `multicast_router` 选项，使桥接充当组播查询器。

```bash
echo 1 > /sys/class/net/br-lan/bridge/multicast_querier
```

## 六、无线桥接

### 6.1 WDS（Wireless Distribution System）
WDS 是一种无线桥接模式，允许接入点之间通过无线链路桥接。OpenWrt 支持 WDS，配置要点：
- 设置 `option mode 'ap'` 和 `option wds '1'`。
- 对端 AP 也需启用 WDS。
- WDS 会使用 4 地址帧格式，可能降低吞吐量。

配置示例（`/etc/config/wireless`）：
```uci
config wifi-iface
        option device 'radio0'
        option mode 'ap'
        option ssid 'MyWDS'
        option wds '1'
        option network 'lan'
```

### 6.2 4 地址模式（4addr）
对于客户端模式（STA）的桥接，需启用 4 地址模式以携带额外的 MAC 地址信息，否则桥接可能无法正常工作。

```uci
config wifi-iface
        option device 'radio0'
        option mode 'sta'
        option ssid 'UpstreamAP'
        option network 'wan'
        option wds '1'          # 启用 4 地址模式
```

### 6.3 Mesh 桥接（802.11s）
OpenWrt 支持 802.11s Mesh 协议，可实现多跳无线 Mesh 网络。Mesh 接口可加入桥接，形成分布式无线骨干。

配置示例：
```uci
config wifi-iface
        option device 'radio0'
        option mode 'mesh'
        option mesh_id 'MyMesh'
        option network 'lan'
```

## 七、桥接与防火墙

### 7.1 桥接流量的防火墙处理
默认情况下，桥接流量**不经过** iptables/nftables 的 `FORWARD` 链，因为桥接是二层转发。但可通过以下内核参数使桥接流量经过 iptables：

```bash
sysctl -w net.bridge.bridge-nf-call-iptables=1
```

启用后，桥接流量将经过 `iptables` 的 `FORWARD` 链，可实现基于 IP 的过滤。

### 7.2 ebtables（二层过滤）
`ebtables` 是专门用于桥接的二层防火墙工具，可基于 MAC 地址、VLAN ID、以太网类型等进行过滤。

安装 ebtables：
```bash
opkg update
opkg install ebtables
```

示例规则：
```bash
# 阻止从 eth0 进入桥接的源 MAC 为 00:11:22:33:44:55 的帧
ebtables -A INPUT -i eth0 -s 00:11:22:33:44:55 -j DROP

# 只允许 VLAN 10 的流量通过
ebtables -A FORWARD -p 802.1Q --vlan-id 10 -j ACCEPT
```

### 7.3 结合 iptables 与 ebtables
在需要同时进行二层和三层过滤的场景中，可同时使用 ebtables 和 iptables。注意处理顺序：ebtables 先于 iptables。

## 八、性能优化

### 8.1 硬件加速
某些 SoC（如 MT7621、IPQ806x）支持硬件桥接加速，可将桥接转发卸载到硬件，大幅提升性能。

启用硬件加速（依平台而异）：
```bash
# 检查是否支持
cat /sys/class/net/br-lan/bridge/hwmode

# 启用硬件加速（示例）
echo "1" > /sys/class/net/br-lan/bridge/hwmode
```

### 8.2 快速路径（Fast Path）
一些开源驱动（如 `mtk_eth_soc`）支持快速路径，允许符合条件的流量绕过 Linux 网络栈，直接由硬件转发。

### 8.3 减少 CPU 负载
- 禁用不必要的桥接功能（如 STP、IGMP snooping）。
- 减少广播流量（避免大广播域）。
- 使用 VLAN 划分缩小广播域。

### 8.4 调整缓冲区与队列
通过 `tc` 调整接口队列长度，避免丢包：
```bash
tc qdisc add dev eth0 root pfifo_fast limit 1000
```

## 九、故障排除

### 9.1 常见问题

#### 桥接未创建或成员接口未加入
- 检查 `/etc/config/network` 中对应接口的 `type` 是否为 `bridge`。
- 确认 `ifname` 列出的接口名称正确且存在（使用 `ip link show` 查看）。
- 查看系统日志：`logread | grep netifd`。

#### 网络环路导致广播风暴
- 启用 STP：`uci set network.lan.stp='1'` 并 `uci reload network`。
- 检查物理拓扑，避免环路。

#### 桥接转发性能差
- 检查 CPU 使用率，桥接转发由 CPU 处理，高速流量可能导致负载升高。
- 考虑使用硬件加速（如某些 SoC 支持硬件桥接）。
- 减少不必要的成员接口，缩小广播域。

#### 无线客户端无法与有线设备通信
- 确认无线接口已加入 LAN 桥接的 `ifname`。
- 检查防火墙规则，确保 `lan` 区域内的转发被允许。
- 使用 `tcpdump` 抓包分析：`tcpdump -i br-lan -n`。

#### 桥接 MAC 地址异常
- 桥接接口的 MAC 地址通常取自第一个成员接口，但有时可能变化。
- 可手动设置 MAC 地址：`uci set network.lan.macaddr='xx:xx:xx:xx:xx:xx'`。

### 9.2 调试命令
```bash
# 查看桥接状态
brctl show
bridge link show

# 查看转发数据库
bridge fdb show

# 抓包分析
tcpdump -i br-lan -n -e

# 查看内核日志
dmesg | grep bridge

# 检查 netifd 日志
logread | grep netifd
```

### 9.3 性能测试
使用 `iperf3` 测试桥接转发性能：
```bash
# 在一台设备上启动服务器
iperf3 -s

# 在另一台设备上启动客户端
iperf3 -c <server_ip> -t 30
```

## 十、面试常见问题

### 10.1 基础概念
1. **桥接与路由的区别是什么？**
   > 桥接工作在数据链路层（L2），根据 MAC 地址转发，所有接口在同一广播域；路由工作在网络层（L3），根据 IP 地址转发，每个接口在不同子网。

2. **OpenWrt 中默认的桥接名称是什么？作用是什么？**
   > 默认桥接名称为 `br-lan`，作用是将有线 LAN 端口和无线 Wi‑Fi 接口桥接在一起，形成统一的局域网。

3. **如何查看当前系统中有哪些桥接？**
   > 使用命令 `brctl show` 或 `ip link show type bridge`。

### 10.2 配置与调试
4. **如何将一个新的物理接口加入现有桥接？**
   > 修改 `/etc/config/network` 中对应桥接的 `ifname` 选项，添加新接口名称，然后执行 `uci commit network` 和 `uci reload network`。

5. **桥接无法转发流量可能的原因有哪些？**
   > 接口未 UP、防火墙阻止、STP 阻塞、MAC 地址表未学习、物理链路故障等。

6. **如何启用 STP 并查看其状态？**
   > 在桥接配置中设置 `option stp '1'`，然后重载配置；使用 `brctl showstp br-lan` 查看状态。

### 10.3 高级问题
7. **什么是 VLAN-aware 桥接？如何配置？**
   > VLAN-aware 桥接允许每个端口配置允许的 VLAN，实现基于 VLAN 的隔离。可通过 `bridge vlan` 命令配置，或通过交换机的硬件 VLAN 功能实现。

8. **无线桥接中 WDS 和 4 地址模式的作用是什么？**
   > WDS 用于接入点间的无线桥接；4 地址模式在客户端模式（STA）下启用，使帧携带额外的 MAC 地址信息，保证桥接正常工作。

9. **如何让桥接流量经过 iptables 过滤？**
   > 设置 `sysctl -w net.bridge.bridge-nf-call-iptables=1`，然后配置 iptables 规则。

10. **硬件桥接加速是什么？如何启用？**
    > 硬件桥接加速将桥接转发卸载到硬件交换机，提升性能。启用方法因平台而异，通常通过设置 `/sys/class/net/br-lan/bridge/hwmode` 或配置 DSA（Distributed Switch Architecture）。

## 十一、总结

桥接是 OpenWrt 网络中实现二层连接的核心组件，尤其在有线与无线融合、多接口统一管理场景中不可或缺。掌握桥接的原理、配置与调试方法，对于 CPE 路由器开发人员至关重要。

### 11.1 最佳实践
1. **明确需求**：是扩展 LAN 还是创建隔离网络？
2. **正确配置**：确保 `type='bridge'` 且 `ifname` 包含所有需要桥接的接口。
3. **注意环路**：在复杂拓扑中启用 STP。
4. **结合防火墙**：通过防火墙规则控制桥接间的流量访问。
5. **性能优化**：利用硬件加速，减少不必要的功能。
