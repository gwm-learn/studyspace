# 5G/LTE 拨号（WWAN）笔记
## 一、概述
CPE 通过 USB/PCIe 挂载 5G 模组，与模组通信的通道分两类：**控制通道**（AT 串口、QMI、MBIM）用于配置与拨号，**数据通道**（qmi_wwan / cdc_mbim 虚拟出的 `wwan0` 网卡）承载业务数据。OpenWrt 中由 netifd 统一管理，把拨号链路抽象为 WWAN 接口，用 uqmi/mbm/comgt 等工具完成注册、拨号、获取地址。

## 二、QMI 与 MBIM 协议简介与对比
### 2.1 QMI（Qualcomm MSM Interface）
高通私有协议，QMUX 封装，承载于 USB 的 CDC WDM 接口。消息采用 TLV 结构，按服务划分：WDS（数据业务）、DMS（设备管理）、NAS（网络状态）等。功能全、性能好，是高通模组（EC20、RM500Q）的主流方案；缺点是非标准，其他厂商支持不一。

### 2.2 MBIM（Mobile Broadband Interface Model）
微软提出、后被 USB-IF 采纳的标准，基于 CDC NCM 扩展。同样用 TLV 消息，服务化划分（Basic Connect、SMS 等）。跨厂商通用，Windows/macOS 原生支持，Linux 用 cdc_mbim 驱动；缺点是封装开销略大。

### 2.3 对比总结
| 维度 | QMI | MBIM |
|------|-----|------|
| 提出者 | 高通（私有） | 微软/USB-IF（标准） |
| 承载接口 | CDC WDM | CDC NCM |
| 内核驱动 | qmi_wwan | cdc_mbim |
| 用户态工具 | uqmi / libqmi | mbimcli / libmbim |
| 生态 | 高通模组、OpenWrt | 全厂商、Windows/macOS |

### 2.4 通道共存
同一模组常同时暴露多个 USB 接口：`/dev/ttyUSB*`（AT 串口）、`/dev/cdc-wdm0`（QMI/MBIM 通道）、`wwan0`（数据网卡），三者独立又配合。

## 三、qmi_wwan / mbim 内核驱动
### 3.1 qmi_wwan
内核自带，驱动高通系 QMI 模组，数据口挂载为 `wwan0`。加载后先确认通道再拨号：
```bash
ls /sys/class/net/       # 应有 wwan0
ls /dev/cdc-wdm0         # QMI 控制通道
dmesg | grep qmi_wwan    # 查看驱动加载日志
```

### 3.2 cdc_mbim
内核自带，驱动标准 MBIM 模组，同样挂载为 `wwan0`，配合 mbimcli 或 mbm 使用。部分模组需先 `ip link set dev wwan0 up` 触发 MBIM 连接。

驱动加载：`modprobe qmi_wwan`（或 `cdc_mbim`），部分模组还需 `modprobe option` 串口驱动。

## 四、AT 指令拨号流程
AT 指令兼容性最好，适合脚本化拨号（comgt、chat）。

### 4.1 拨号流程与常用指令
```
AT                  -> 测试串口
AT+CPIN?            -> 检查 SIM 卡（READY 才可拨号）
AT+CREG? / AT+CEREG?-> 查询注册状态（0,1 或 0,5 表示已注册）
AT+CGDCONT=1,"IP","apn" -> 设置 PDP 上下文（APN）
ATD*99***1#         -> 发起 PPP 拨号
AT+CSQ              -> 信号强度（RSSI 0~31，越大越好）
AT+COPS?            -> 当前运营商
AT+CGACT=1,1        -> 激活 PDP 上下文
AT+CGPADDR=1        -> 查询 PDP 分配的 IP
```
适用场景：老模组、无 QMI/MBIM 驱动时兜底；故障排查首选手段；PPP 封装有额外开销，性能要求高时不推荐。

## 五、OpenWrt 中的 5G 模块配置
### 5.1 工具选择
| 工具 | 协议 | 包名 | 适用 |
|------|------|------|------|
| uqmi | QMI | `uqmi` | 高通系模组，官方推荐 |
| mbimcli | MBIM | `mbimcli` | 标准 MBIM 模组 |
| mbm | MBIM | `mbm` | 简化版 MBIM 拨号脚本 |
| comgt | AT | `comgt` | 传统 AT/PPP 拨号 |

### 5.2 uqmi 手动拨号（QMI 示例）
```bash
uqmi -d /dev/cdc-wdm0 --set-device-operating-mode online
uqmi -d /dev/cdc-wdm0 --set-ip-family ipv4
uqmi -d /dev/cdc-wdm0 --start-network "internet" --apn "internet" --auth-type pap
uqmi -d /dev/cdc-wdm0 --get-data-status
```

### 5.3 netifd 集成（/etc/config/network）
OpenWrt 中 `proto qmi` 由 netifd 调用 uqmi 自动拨号：
```
config interface 'wwan'
        option proto 'qmi'
        option device '/dev/cdc-wdm0'
        option apn 'cmnet'
        option auth 'pap'
        option pdptype 'ipv4'
```
另有 `proto mbim`（调 mbimcli）和 `proto 3g`（调 comgt，AT/PPP 方式）。改完后 `ifup wwan` 或 `service network restart` 生效。

## 六、APN 配置
APN 决定走哪个运营商网关，配错直接导致无法上网。
### 6.1 常见 APN
| 运营商 | APN |
|--------|-----|
| 中国移动 | cmnet（公网）/ cmwap |
| 中国联通 | 3gnet / wonet |
| 中国电信 | ctnet |

### 6.2 配置要点
- QMI/MBIM 方式：UCI 中 `option apn` 配置；AT 方式：`AT+CGDCONT=1,"IP","apn"`。
- 物联网卡多用专用 APN，需向运营商确认；认证（auth）用 PAP/CHAP/none，与运营商约定一致。
- 验证生效值：`uqmi -d /dev/cdc-wdm0 --get-current-settings`。

## 七、信号质量查询
### 7.1 查询方式
```bash
uqmi -d /dev/cdc-wdm0 --get-signal-info    # QMI，输出 rssi/rsrq/rsrp/snr
mbimcli -d /dev/cdc-wdm0 --query-signal-state   # MBIM
AT+CSQ    # AT 方式，RSSI 0~31，越大越好
```

### 7.2 信号指标说明
- **RSRP**：参考信号接收功率，5G 一般 -90 dBm 以上为好，-110 dBm 以下较差。
- **RSRQ**：参考信号接收质量，越高越好。
- **SINR/SNR**：信噪比，越大越好（10 dB 以上较好）。
- 以 RSRP 为主判断信号覆盖，结合 SINR 判断干扰。

## 八、多 PDN 会话
多 PDN 指一个模组同时建立多个数据连接，典型场景是"数据通道 + 管理通道"分离（TR069 走专网、业务走公网）。

### 8.1 QMI 多 PDN 配置
- uqmi 用 `--cid` 指定连接 ID，每个 cid 对应一个 PDN；netifd 中创建多个 `qmi` 接口并指定 cid：
```
config interface 'wwan_data'
        option proto 'qmi'
        option device '/dev/cdc-wdm0'
        option apn 'cmnet'
        option cid '1'

config interface 'wwan_mgmt'
        option proto 'qmi'
        option device '/dev/cdc-wdm0'
        option apn 'special.apn'
        option cid '2'
```
- 多 PDN 依赖 QMAP（qmi_wwan 的 mux）能力，把多个 PDN 映射到多个 `wwanX` 网卡。

### 8.2 注意事项
- 模组需支持多 PDP 上下文（一般 8 路以上），运营商可能限制 PDN 数量。
- 每个 PDN 独立配置 APN、认证、路由；不同 PDN 流量需用 `ip rule` 策略路由区分，否则回程路由冲突。
- 与 mwan3 多 WAN 配合可实现专网/公网通道并存。

## 九、常见问题排查
| 现象 | 排查思路 |
|------|----------|
| wwan0 不出现 | 检查驱动、USB 枚举、`dmesg` 中 qmi_wwan 报错 |
| 拨号超时 | 先 `AT+CPIN?` 确认 SIM 就绪，`AT+CEREG?` 确认注册 |
| 有信号上不了网 | 检查 APN、认证方式、PDN 类型（IPV4/IPV6） |
| 速度慢 | 查询信号质量，确认是否掉到 4G/3G，检查天线 |
| 掉线频繁 | 检查 USB autosuspend 休眠/省电策略 |

## 十、小结
- 选型：高通模组优先 QMI（uqmi），标准模组用 MBIM，老模组兜底用 AT（comgt）。
- 配置统一收敛到 netifd，UCI 的 `proto` 决定底层工具。
- 排查顺序：驱动 → SIM/注册 → APN → 信号 → 路由。
- 多 PDN 是 CPE 管理通道与业务通道隔离的关键能力。
