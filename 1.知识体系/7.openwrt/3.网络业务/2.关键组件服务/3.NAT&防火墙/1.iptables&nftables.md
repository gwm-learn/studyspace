# OpenWrt 防火墙：iptables 与 nftables

## 一、防火墙框架演变：fw3 → fw4

OpenWrt 防火墙分两层：上层是 UCI 配置（`/etc/config/firewall`），下层是执行规则的内核防火墙工具。

| 版本 | 内核框架 | 前端脚本 | 特点 |
|------|----------|----------|------|
| 19.07 及之前 | iptables（legacy/netfilter） | **fw3** | 经典方案，规则基于 table-chain 模型 |
| 22.03 之后 | **nftables** | **fw4** | 内核默认加载 nftables，iptables 仅作兼容层 |

### 1.1 为什么迁移到 nftables
- **统一框架**：iptables/ip6tables/arptables/ebtables 四套工具合一，一套语法同时管理 IPv4/IPv6。
- **性能更好**：规则集在用户态编译后一次性加载，批量更新而非逐条下发；内置集合（set）简化重复规则。
- **语法更直观**：`table → chain → rule` 三级结构，规则按顺序执行。

### 1.2 fw3 与 fw4 的关系
- fw3 用 `iptables-restore` 加载规则，fw4 用 `nft -f` 加载，共用同一个 `/etc/config/firewall`。
- 22.03 之后命令行即使还用 `iptables`，实际也是 nft 兼容层，规则最终都进 nftables。

## 二、iptables 在 OpenWrt 中的使用

### 2.1 自定义规则放置位置
- **`/etc/firewall.user`**：最常用的自定义脚本，防火墙 reload 时自动执行。
- `/etc/firewall.include`：被调用的通用函数与初始化变量。
- `/etc/hotplug.d/firewall/`：防火墙热插拔脚本目录。

示例（fw3 风格）：`iptables -A input_wan -p tcp --dport 22 -j ACCEPT`。fw4 下该文件仍生效，但建议优先用 UCI 方式表达。

### 2.2 LuCI 图形化配置
LuCI「网络 → 防火墙」页面操作的就是 `/etc/config/firewall`：
- **常规设置**：对应 `defaults` 节（默认 input/output/forward 策略、SYN flood 防护）。
- **端口转发**：对应 `redirect` 节，配置 WAN → LAN 的 DNAT 规则。
- **通信规则**：对应 `rule` 节，通用的 allow/drop 规则。
- **区域**：对应 `zone` 节，管理 LAN/WAN/GUEST 等区域间转发关系。

## 三、nftables 基础

### 3.1 三级结构：table / chain / rule
`table`（表）包含若干 `chain`（链），链指定钩子点（hook）与优先级，链内按顺序执行 `rule`（匹配条件 + 动作）。

常用命令：`nft add table inet mytable`（建表）、`nft add chain inet mytable input { type filter hook input priority 0 \; }`（建链）、`nft add rule inet mytable input iif "lo" accept`（加规则）、`nft list ruleset`（查看）。

### 3.2 与 iptables 语法对比

| 概念 | iptables | nftables |
|------|----------|----------|
| 表（filter/nat/mangle） | `iptables -t filter ...` | 表内用 chain 区分 |
| 链（INPUT/FORWARD...） | `iptables -A INPUT ...` | `nft add rule <table> <chain> ...` |
| 链归属 | 固定 5 张表、内置链 | 表/链名可任意自定义 |
| 匹配端口 / 接口 | `-p tcp --dport 80` / `-i eth0` | `tcp dport 80` / `iif "eth0"` |
| 动作 | `-j ACCEPT / DROP` | `accept / drop` |
| 批量加载 | `iptables-restore` | `nft -f ruleset.nft` |
| 集合/映射 | 需要 ipset | 内置 `set`、`map` |

### 3.3 fw4 生成的规则集

实际规则集在 `/tmp/fw4.nft`（fw3 对应 `/tmp/rules.ipt`），用 `nft list ruleset` 查看全部规则、`nft list table inet fw4` 查看 fw4 生成的表。

## 四、常用配置场景

### 4.1 允许特定端口（打开入站端口）
```uci
config rule
    option name 'Allow_HTTP_WAN'
    option src 'wan'
    option dest_port '80'
    option proto 'tcp'
    option target 'ACCEPT'
```

### 4.2 端口转发（端口映射，DNAT）
把 WAN 的 8080 端口转发到内网主机 192.168.1.10 的 80 端口：
```uci
config redirect
    option name 'WebServer'
    option src 'wan'
    option src_dport '8080'
    option dest 'lan'
    option dest_ip '192.168.1.10'
    option dest_port '80'
    option proto 'tcp'
```

### 4.3 区域间策略
zone 定义区域默认行为，forwarding 定义区域间转发方向（lan→wan 允许上网）：
```uci
config zone 'lan'
    option input 'ACCEPT'
    option output 'ACCEPT'
    option forward 'ACCEPT'
config zone 'wan'
    option input 'REJECT'
    option output 'ACCEPT'
    option forward 'REJECT'
config forwarding
    option src 'lan'
    option dest 'wan'
```

## 五、/etc/config/firewall 关键节

| 节类型 | 作用 | 常用 option |
|--------|------|-------------|
| `defaults` | 全局默认策略 | `input`/`output`/`forward`、`syn_flood` |
| `zone` | 定义防火墙区域 | `name`、`network`、`input`/`output`/`forward` |
| `forwarding` | 区域间转发策略 | `src`、`dest`（如 lan→wan 上网） |
| `rule` | 通用过滤规则 | `src`/`dest`、`proto`、`dest_port`、`target` |
| `redirect` | 端口转发/DNAT | `src`/`dest`、`src_dport`、`dest_ip`、`dest_port` |
| `include` | 引入外部脚本 | `path`（如 `/etc/firewall.user`） |

生效命令：`/etc/init.d/firewall reload`（推荐，不中断连接）；`restart`（完全重启，可能短暂断网）。

## 六、总结

- **框架选择**：22.03 起默认 fw4 + nftables，iptables 仅是兼容层，新开发一律面向 nftables。
- **配置入口**：改 `/etc/config/firewall`（UCI）或 `/etc/firewall.user`，不要直接编辑系统生成的规则文件。
- **排查手段**：reload 后用 `nft list ruleset` 核对规则是否符合预期。
