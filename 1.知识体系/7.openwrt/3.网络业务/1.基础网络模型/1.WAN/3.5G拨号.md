# OpenWrt 中 5G/LTE 模块拨号（WAN 视角）

## 一、概述
5G CPE 通过 USB/PCIe 挂载 5G 模组，OpenWrt 把拨号链路抽象为 WWAN 接口，由 netifd 统一管理。与模组通信分**控制通道**（配置、拨号）和**数据通道**（`wwan0` 网卡承载业务）。协议原理（QMI/MBIM/AT 对比、uqmi 手动拨号、多 PDN）见 [5G 拨号原理笔记](./../../2.关键组件服务/7.5G拨号/5G拨号.md)，本文聚焦 OpenWrt 中的 WAN 集成与链路检测。

## 二、三种拨号方式
OpenWrt 通过 UCI 的 `proto` 字段决定底层拨号工具：

| proto | 底层工具 | 通道 | 适用场景 |
|-------|----------|------|----------|
| `qmi` | uqmi / libqmi | /dev/cdc-wdm0 | 高通系模组（EC20、RM500Q），官方推荐 |
| `mbim` | mbimcli / mbm | /dev/cdc-wdm0 | 标准 MBIM 模组，跨厂商 |
| `3g` | comgt + chat | /dev/ttyUSB* | 老模组，AT/PPP 拨号兜底 |

### 2.1 QMI 方式（/etc/config/network）
```uci
config interface 'wwan'
        option proto 'qmi'
        option device '/dev/cdc-wdm0'
        option apn 'cmnet'
        option auth 'pap'
        option pdptype 'ipv4'
        option pincode '1234'
        option delay '10'
```
- `device`：QMI 控制通道设备节点
- `pincode`：SIM 卡 PIN 码，未启用可省略
- `delay`：模组上电到就绪的等待时间（秒），防启动竞态

### 2.2 MBIM 方式
```uci
config interface 'wwan'
        option proto 'mbim'
        option device '/dev/cdc-wdm0'
        option apn 'cmnet'
        option auth 'pap'
        option pdptype 'ipv4'
```
部分模组需先 `ip link set dev wwan0 up` 才能建立会话。

### 2.3 AT 方式
```uci
config interface 'wwan'
        option proto '3g'
        option device '/dev/ttyUSB2'
        option apn 'cmnet'
        option pincode '1234'
        option username 'card'
        option password 'card'
```
底层由 comgt 执行 `AT+CGDCONT` 设置 APN，再 `ATD*99#` 发起 PPP 拨号。

## 三、APN 配置
APN 决定数据走哪个运营商网关，配错直接导致无法上网。

### 3.1 常见 APN
| 运营商 | APN | 备注 |
|--------|-----|------|
| 中国移动 | `cmnet` | 公网 |
| 中国联通 | `3gnet` / `wonet` | |
| 中国电信 | `ctnet` | |

### 3.2 配置要点
- UCI 中统一用 `option apn` 配置，netifd 转换为各工具的拨号参数
- 物联网卡多用运营商下发的专用 APN，需向运营商确认
- `auth`（认证方式）用 `pap` / `chap` / `none`，与运营商约定一致，配错会拨号失败
- `pdptype` 决定 IP 类型：`ipv4` / `ipv6` / `ipv4v6`（双栈）

## 四、链路检测
5G 链路稳定性差，CPE 需要主动探测并自动恢复，否则"有信号上不了网"。

### 4.1 检测手段
1. **ping 检测**：周期性 ping 对端（如 114.114.114.114），连续失败判定链路断开
2. **模组状态查询**：查询注册状态与数据连接状态，拨号断开时重新触发拨号
3. **netifd 事件**：接口 down 后由 hotplug 脚本触发重拨

```bash
uqmi -d /dev/cdc-wdm0 --get-data-status    # QMI：connected 表示在网
uqmi -d /dev/cdc-wdm0 --get-signal-info    # 信号：rssi/rsrq/rsrp/snr
```

### 4.2 自动重拨
- netifd 对 `qmi`/`mbim` 接口在拨号失败时自动重试
- 配合 `ifup wwan` 在检测脚本中手动恢复：
```bash
ping -c 3 -W 2 114.114.114.114 || {
        ifdown wwan
        sleep 5
        ifup wwan
}
```
- 生产 CPE 常用心跳保活：接口 up 后启动守护脚本，定期 ping + 查 `get-data-status`，异常即重拨

### 4.3 多 WAN 冗余
5G 常与有线 WAN 组成多 WAN，用 mwan3 按优先级或负载均衡分流，5G 掉线时自动切换，避免业务中断。

## 五、常见排查
| 现象 | 排查思路 |
|------|----------|
| wwan0 不出现 | `dmesg \| grep qmi_wwan`，确认 USB 枚举与驱动 |
| 拨号失败 | `AT+CPIN?` 查 SIM 状态，`AT+CEREG?` 查注册 |
| 有信号无网络 | 核对 APN、auth、pdptype，查看 `get-data-status` |
| 频繁掉线 | 检查 USB autosuspend 休眠策略，信号质量差加天线 |
| 速度慢 | 查信号指标（RSRP/SINR），确认是否回落到 4G |
