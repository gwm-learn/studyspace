# OpenWrt 中 DHCP Client（WAN 口动态获取地址）

## 一、概述
OpenWrt 的 WAN 口通过 `proto dhcp` 配置时，由 netifd 调用 **udhcpc**（BusyBox 自带的 DHCP 客户端）向上游 DHCP 服务器请求地址。这是光猫路由模式、上级路由器、有线宽带的典型接入方式。协议细节见 [DHCP 协议](./../../../../../3.协议应用/4.dhcp/DHCP.md)。

## 二、udhcpc 工作流程
### 2.1 交互流程
udhcpc 遵循标准 DHCP 四步握手：

```
Discover -> Offer -> Request -> Ack
```

1. 接口 up 后，udhcpc 广播发送 **Discover** 报文（源 IP 0.0.0.0）
2. 服务器回复 **Offer**，携带候选 IP 和租期
3. udhcpc 发送 **Request** 确认选用该地址
4. 服务器回复 **Ack**，udhcpc 通过脚本配置地址并上报 netifd

### 2.2 租期续约
- 默认租期 12 小时（`option leasetime` 可由服务器决定）
- 在 **50% 租期**（T1）时单播续约，失败后在 **87.5%**（T2）时广播续约
- 续约失败会重试，最终租期耗尽后重新走 Discover

### 2.3 脚本机制
udhcpc 获取到地址后执行 `/usr/share/udhcpc/default.script`，脚本完成 IP、路由、DNS 的配置并通知 netifd 更新接口状态。自定义事件可通过 `option script` 覆盖。

## 三、UCI 配置
`/etc/config/network` 中 WAN 接口示例：

```uci
config interface 'wan'
        option proto 'dhcp'
        option ifname 'eth0.2'
        option hostname 'MyRouter'
        option clientid '01:aa:bb:cc:dd:ee:ff'
        option vendorid 'openwrt'
        option reqopts '1 3 6 15 28 121'
        option force_dhcp '0'
```

常用选项说明：
- `hostname`：DHCP 报文中的主机名选项（option 12），部分运营商据此下发地址
- `clientid`：客户端标识（option 61），绑定同一地址的关键
- `vendorid`：厂商标识（option 60），运营商用于区分设备类型
- `reqopts`：请求的 option 列表，按 DHCP option 编号指定，如 1（掩码）、3（网关）、6（DNS）
- `force_dhcp`：强制 DHCP，`1` 时即使有静态配置也发起请求

## 四、默认路由
udhcpc 拿到地址后，netifd 会自动生成默认路由：

- **路由来源**：DHCP 的 option 3（Router）指定网关
- **路由表**：默认写入 `default` 表，metric 由接口顺序决定
- **多 WAN**：配合 mwan3 时按接口划分独立路由表，`ip rule` 做策略路由分流

查看确认：
```bash
ip route show
ip route show table all
```

## 五、DNS 与 resolv.conf
DHCP 下发的 DNS（option 6）由 udhcpc 写入 `/tmp/resolv.conf.auto`，dnsmasq 通过 `resolv-file` 读取并作为上游转发。可通过 `uci show dhcp` 查看 dnsmasq 的 `resolvfile` 指向。

## 六、常见排查
| 现象 | 排查思路 |
|------|----------|
| 获取不到 IP | `logread \| grep udhcpc` 看 Discover/Offer 是否往返 |
| 地址频繁变化 | 上游开启了 IPoE/接入鉴权，需配置 clientid/hostname |
| 拿到的地址不能上网 | 运营商做 MAC/设备绑定，需克隆 MAC（`option macaddr`） |
| 路由缺失 | `ip route show` 确认网关，检查上游是否下发 option 3 |
