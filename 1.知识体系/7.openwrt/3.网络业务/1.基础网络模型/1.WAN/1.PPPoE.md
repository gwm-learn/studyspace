# OpenWrt 中 PPPoE 拨号配置

## 一、概述
PPPoE（Point-to-Point Protocol over Ethernet）是运营商宽带接入最常用的拨号方式，把 PPP 会话承载在以太网上，通过用户名/密码认证后动态获取公网 IP。在 OpenWrt 中，PPPoE 由 `pppd` 进程实现，netifd 通过 `proto pppoe` 统一管理，配置集中在 `/etc/config/network`。底层协议细节见 [PPPoE 协议](./../../../../../3.协议应用/6.pppoe/pppoe.md)。

## 二、UCI 配置
### 2.1 基本配置
`/etc/config/network` 中 WAN 接口示例：

```uci
config interface 'wan'
        option proto 'pppoe'
        option ifname 'eth0.2'
        option username 'user@adsl'
        option password '123456'
        option keepalive '5'
        option demand '0'
```

各选项说明：
- `proto`：协议类型，PPPoE 固定为 `pppoe`
- `ifname`：承载 PPPoE 会话的物理以太网口，接光猫时常用 VLAN 子接口（如 `eth0.2`）
- `username` / `password`：运营商下发的拨号账号密码，常带 `@` 域名后缀
- `keepalive`：LCP 保活探测间隔（秒），`0` 表示关闭保活
- `demand`：按需拨号，`0` 表示永久在线（CPE 场景必须为 0，避免静默掉线）

修改后执行 `uci commit network && uci reload network`，或直接 `ifup wan` 立即拨号。

## 三、PAP/CHAP 认证
PPPoE 使用 PPP 的链路控制协商认证，OpenWrt 的 pppd 通过 `pap-secrets` / `chap-secrets` 认证文件配合 UCI 工作：

- **PAP（Password Authentication Protocol）**：明文传输密码，认证简单但安全性差
- **CHAP（Challenge Handshake Authentication Protocol）**：挑战-应答方式，密码不直接在线路上传输，安全性更高

OpenWrt 一般不需要显式指定认证协议，pppd 在协商阶段自动与运营商侧协商出双方都支持的方式。若需强制指定，可在 UCI 中通过 `pppd_options` 追加参数：

```uci
config interface 'wan'
        option proto 'pppoe'
        option pppd_options 'require-pap'
```

多数光猫 PPPoE 拨号实际协商出的都是 CHAP。排查认证问题时用 `logread | grep pppd` 查看日志，重点关注 `PAP authentication succeeded` / `CHAP authentication succeeded` 字样。

## 四、MTU/MRU 配置
PPPoE 封装在以太网帧上，额外增加了 8 字节 PPPoE 头，导致标准以太网 MTU（1500）会引发分片。pppd 默认把 MTU/MRU 协商为 **1492**：

- **MTU（Maximum Transmission Unit）**：IP 层最大发送长度
- **MRU（Maximum Receive Unit）**：IP 层最大接收长度

两者在 PPP 协商中同时声明，通常取 1492。若运营商侧或防火墙限制特殊，可手动调整：

```uci
config interface 'wan'
        option proto 'pppoe'
        option mtu '1492'
        option mru '1492'
```

注意：若启用 PPPoE 的 MSS 钳制（默认开启），TCP 大包会按 MTU 自动修正，改 MTU 后需同步确认防火墙的 `mtu_fix` 规则仍在生效，否则大包无法通过。

## 五、常见排查
| 现象 | 排查思路 |
|------|----------|
| 拨号失败 | `logread \| grep pppd` 看 LCP/PAP/CHAP 阶段日志 |
| 认证失败 | 检查 username/password，确认是否带 `@adsl` 域名 |
| 反复掉线 | `option keepalive '5'` 保活探测，检查线路质量 |
| 大包不通 | 核对 MTU，用 `ping -s 1472 -M do` 测试分片限制 |
| 获取不到 IP | 确认光猫是否已桥接（不能是路由模式） |
