# Linux 内核收发包流程

# 概述

数据包在内核中的路径分为两条：**收包路径（RX）**和**发包路径（TX）**。收包从网卡硬件收到数据开始，经过驱动、中断/软中断、协议栈，最终交给用户空间 socket；发包则反向，从用户空间 socket 开始，经过传输层、网络层、邻居子系统、流量控制（Qdisc）和驱动，最终写入网卡硬件。

两条路径以**网卡驱动**为分界：驱动以下是与硬件打交道的收发包，驱动以上是内核协议栈的处理。中间通过 `struct sk_buff`（skb）这个核心数据结构承载数据，每个包在内核中就是一个 skb。# 收包路径

## 1. 网卡驱动收包

网卡收到数据后通过 DMA 把数据写入内存中的**环形缓冲区（ring buffer）**，然后产生硬中断通知 CPU。驱动在中断处理函数 `xxx_rx()` 中读取 ring buffer 中已就绪的描述符，通过 `napi_gro_receive()` 或 `netif_receive_skb()` 把数据交给协议栈。

- **DMA 环形缓冲区**：驱动初始化时分配，网卡直接写入，减少拷贝。
- **NAPI**：驱动注册 `struct napi_struct`，通过 `poll()` 批量收包，避免每个包都触发一次硬中断。
- **GRO（Generic Receive Offload）**：`napi_gro_receive()` 先把多个小包合并成一个大包再上交，减少协议栈处理次数。

## 2. NAPI 软中断

收包处理主要在**软中断（softirq）**中执行，流程如下：

1. 网卡硬中断 → 驱动中断处理函数：屏蔽中断、置位 NAPI、唤醒 `NET_RX_SOFTIRQ` 软中断。
2. 软中断核心 `net_rx_action()` 遍历被唤醒的 NAPI 实例列表，逐个调用驱动的 `poll()`。
3. `poll()` 循环从 ring buffer 取包（`GRO` 合并后），调用 `napi_gro_receive()` → `__netif_receive_skb()` → `netif_receive_skb()`，把 skb 送入协议栈。
4. 每轮 `poll()` 有 `budget`（默认 300）额度限制，防止软中断饿死其他任务；取完或额度耗尽后退出，必要时重新触发。硬中断处理时间被压到最短，这是 NAPI 的设计核心。

## 3. netif_receive_skb 与协议栈分发

`netif_receive_skb()`（实际是 `__netif_receive_skb_core()`）是收包进入协议栈的入口，它做的事：

1. 处理 **tc ingress** 挂载点，即 `tc filter` 的 ingress 方向规则。
2. 经过 **Netfilter** 的 `PREROUTING` 钩子（`nf_hook`），实现 DNAT、防火墙、桥接过滤等。
3. 判断包类型（`skb->protocol`）并交给对应的 `packet_type` 处理函数：IP 包进入 `ip_rcv()`，ARP 进入 `arp_rcv()`，也支持原始套接字（AF_PACKET）。

## 4. IP 层处理

`ip_rcv()` 开始 IP 层处理，核心路径：

- 检查版本、校验和、长度等合法性。
- `ip_rcv_finish()` 调用 `ip_route_input_noref()` 路由查找，决定是**本机接收**还是**转发**：
  - 本机接收：进入 `ip_local_deliver()`，经 `NF_INET_LOCAL_IN` 钩子后按协议分发。
  - 转发：进入 `ip_forward()`，经 `NF_INET_FORWARD` 钩子，然后走 `ip_output()`（发送路径）。
- 开启 **iptables** 时，`mangle`/`nat`/`filter` 表挂在上述各钩子上执行规则匹配。

## 5. 传输层分发到 socket

本机接收的包进入 `ip_local_deliver()` 后，根据 `skb->protocol`（`IPPROTO_TCP` / `IPPROTO_UDP` / `IPPROTO_ICMP`）交给传输层：

- **TCP**：`tcp_v4_rcv()`，通过 4 元组（源/目的 IP、源/目的端口）查找连接，送入对应 socket 的接收队列，触发 `epoll`/`select` 唤醒等待进程。
- **UDP**：`udp_rcv()`，通过 4 元组查 UDP socket 哈希表，投递到 socket 接收缓冲区。
- **ICMP**：`icmp_rcv()`，处理 ping 等，或上报错误。

传输层到 socket 的交付依赖 **socket 哈希表**（如 TCP 的 `ehash`、UDP 的 `udp_table`）。用户空间进程最终通过 `recvmsg()`/`read()` 从 socket 缓冲区取走数据，收包路径结束。

收包总览：

```
网卡 → DMA ring buffer → 硬中断 → NAPI 软中断 → netif_receive_skb → PREROUTING → 路由
  → 本机: ip_local_deliver → LOCAL_IN → TCP/UDP → socket
  → 转发: ip_forward → FORWARD → ip_output（进入发送路径）
```

# 发送路径

## 1. socket 到传输层

用户进程调用 `send()`/`write()` 把数据写入 socket。socket 层把数据封装成 skb 后调用传输层发送接口：

- **TCP**：`tcp_sendmsg()` → `tcp_write_xmit()`，按拥塞窗口发送，通过 `ip_queue_xmit()` 交给 IP 层。
- **UDP**：`udp_sendmsg()` → `ip_append_data()` / `ip_push_pending_frames()`，构造好 UDP 头后调用 `ip_local_out()`。
- 此处同时完成端口、校验和、分段（TCP 分段由发送侧完成）等封装，发送路径由此开始。

## 2. 传输层到 IP 层

IP 层发送核心是 `ip_output()` 及 `ip_finish_output()`：

- 查路由确定**出口设备**和下一跳（`ip_route_output_flow()`）。
- 经过 Netfilter `NF_INET_LOCAL_OUT` 钩子，执行 OUTPUT 链（如 NAT 的 SNAT、防火墙）。
- `ip_finish_output()` 调用 `ip_finish_output2()`，通过 **邻居子系统** 解析二层信息。

## 3. 邻居子系统

`ip_finish_output2()` 调用邻居子系统（`neigh_output()` / `neigh_resolve_output()`）：

- 通过 ARP（IPv4）或 NDP（IPv6）解析下一跳的 **MAC 地址**，填充以太网头。
- 若邻居条目已缓存，直接构造二层头；未缓存则发出 ARP 请求，skb 挂起等待应答。
- 邻居解析完成后调用 `dev_queue_xmit()` 进入流量控制层。

## 4. Qdisc 排队

`dev_queue_xmit()` 是流量控制的入口，把 skb 送入出口设备的**排队规则（Qdisc）**：

- 默认 `pfifo_fast` 按优先级入队，OpenWrt 上常用 `htb`、`fq_codel` 实现限速与公平调度。
- 队列满时触发拥塞控制（如 TCP 背压），否则调度器按规则取包，调用驱动的发送函数。
- 这里对应 **tc egress** 方向，即 `tc filter` 的出口规则。

## 5. 驱动发送

Qdisc 取出 skb 后调用 `ndo_start_xmit()`（驱动注册的 `net_device_ops` 发送方法）：

- 驱动把 skb 数据通过 DMA 映射到 ring buffer，通知网卡硬件发送。
- 若 ring buffer 已满，返回 `NETDEV_TX_BUSY`，Qdisc 稍后重试。
- 发送完成后硬中断确认，回收 skb 与 DMA 映射（NAPI 的 poll 里顺便处理发送完成队列）。

发送总览：

```
socket → TCP/UDP → IP 层（路由 + OUTPUT 链）→ 邻居子系统（ARP/NDP）
  → dev_queue_xmit → Qdisc（tc egress）→ ndo_start_xmit → DMA → 网卡
```

# 软中断与硬中断小结

| 项目 | 硬中断（hardirq） | 软中断（softirq） |
|------|-------------------|-------------------|
| 触发 | 网卡收到/发完数据 | 硬中断处理中 `raise_softirq` 触发 |
| 处理 | 收包：置位 NAPI；发包：回收 skb | 收包：`net_rx_action()` 轮询 NAPI；发包：发送完成处理 |
| 特点 | 快进快出，不能长时间占用 | 可被打断，受 budget 限制 |
| 关闭 | 不可被中断 | 可被硬中断打断 |

理解收发包流程是分析 OpenWrt 网络问题的前提：丢包可能在驱动 ring buffer、NAPI budget、Netfilter 钩子、Qdisc 队列或 socket 缓冲区任一环节发生，排查时按路径逐段定位。
