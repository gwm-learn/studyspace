# USB 子系统

# 概述

USB 子系统是 Linux 内核中设备模型最典型的代表，分三层：**控制器驱动（HCD）**、**核心层（usbcore）**、**设备驱动（class/function）**。核心层位于 `drivers/usb/core/`，负责枚举、urb 管理、设备/接口管理。OpenWrt 中 4G/5G 模组、WiFi 网卡、U 盘都挂在 USB 总线上，理解枚举和 CDC 类驱动是排查模组识别问题的前提。

# USB 枚举流程

USB 是**树形拓扑 + 轮询**总线，没有地址概念，靠**地址 + 端点**寻址。设备插入后由主机驱动枚举：

1. **检测连接**：HCD 检测到端口电平变化（D+ 上拉），上报连接事件。
2. **复位与分配地址**：内核给设备发 `SET_ADDRESS`，分配 1-127 的地址。
3. **读描述符**：主机依次请求设备描述符（`GET_DESCRIPTOR`）：
   - 设备描述符：`bDeviceClass`、`idVendor`/`idProduct`、`bNumConfigurations`。
   - 配置描述符：`bNumInterfaces`，一个配置含多个接口。
   - 接口描述符：`bInterfaceClass`（如 0x02 CDC、0x0A CDC-Data）、`bInterfaceSubClass`、`bInterfaceProtocol`。
   - 端点描述符：方向、传输类型（控制/批量/中断/同步）、最大包长。
4. **选配置**：内核调 `usb_set_configuration()`，加载该配置的所有接口。
5. **绑定驱动**：接口级 match，`usb_register_driver()` 的 `probe` 被调用。

关键数据结构：`struct usb_device`（整个设备）、`struct usb_interface`（驱动绑定单位）、`struct urb`（异步传输请求）。`lsusb -v` 可查看完整描述符树。

# CDC 类驱动与 RNDIS/ECM/QMI

模组上网的核心是 CDC（Communication Device Class）**通信设备类**，OpenWrt 中 4G/5G 模组按接口协议加载不同驱动：

## 1. ECM（Ethernet Control Model）

- 类代码 `0x02` + 子类 `0x06`，数据面走**批量端点**，内核驱动 `cdc_ether`。
- 模组虚拟成一张以太网卡（`eth1`），跑 DHCP/静态 IP，无需拨号。
- 典型场景：老式 4G 模组、华为 3G/4G 模块默认模式。

## 2. RNDIS（Remote NDIS）

- 微软定义的"USB 上的以太网"，类代码 `0x02` + 子类 `0x02` + 协议 `0xFF`（厂商私有）。
- 内核驱动 `rndis_host`，同样虚拟出网卡，但协议是微软私有格式，Linux 端需要 `rndis_host` 识别。
- 不少模组出厂默认 RNDIS，OpenWrt 下常通过 `usb-modeswitch` 切换到 ECM/QMI 以获得原生协议。

## 3. QMI / MBIM

- **QMI**（Qualcomm MSM Interface）：高通私有协议，接口协议 `0xFF`，驱动 `qmi_wwan`。控制面走 QMI 消息（建立数据会话），数据面是 wwan0 网卡。OpenWrt 用 `uqmi` + `proto qmi` 拨号，需 AT 指令先切到 QMI 模式。
- **MBIM**：USB-IF 标准化版 QMI，驱动 `cdc_mbim`，`ModemManager` 原生支持，`proto mbim` 拨号。

三者的数据面都是"USB 网卡"，区别在控制面协议：ECM 零配置、RNDIS 微软私有、QMI/MBIM 带会话管理，能下发 PDP 上下文参数。

# usb-modeswitch

模组出厂通常固化为**存储卡 + 串口**形态（方便装驱动），不是上网形态。`usb-modeswitch` 负责把模组从"存储模式"切换到"上网模式"：

```
插入模组（VID:PID 为存储模式，如 12d1:1f01）
  → usb-modeswitch 按配置发控制传输（SCSI 或厂商命令）
  → 模组重新枚举为上网模式（VID:PID 变化，如 12d1:1506）
  → 重新枚举后加载 cdc_ether / qmi_wwan / option 驱动
```

- 配置在 `/etc/usb-modeswitch.d/`，按 `VID:PID` 匹配，内容是一组控制请求。
- OpenWrt 中由 `usbmode` 脚本（netifd 的 usb 触发）自动执行，`option 'modem'` 的接口依赖它先切换模式。
- 调试：`usb_modeswitch -v <vid> -p <pid> -W` 手动切换，`lsusb` 观察 VID:PID 变化。

# 串口 AT 通道

上网模式下的模组通常暴露一个或多个 **ttyUSB**（`usb-serial` 驱动，`option`/`qcserial`），用于 AT 指令：

- 发送 `AT` 返回 `OK` 验证通道，`AT+CGDCONT` 配 APN，`ATD*99#` 拨号。
- OpenWrt 里 `proto '3g'` 用 pppd + 串口 AT 拨号；QMI 模式则用 `uqmi` 走 QMI 通道。
- 多 tty 端口分工：`ttyUSB0` 控制、`ttyUSB1` 数据，端口映射由模组决定。

# 调试要点

- `lsusb` 看设备树与 VID:PID；`lsusb -t` 看驱动绑定树（哪个驱动占用哪个接口）。
- `dmesg | grep usb` 看枚举与驱动加载日志，识别 `New USB device found` 后的描述符。
- `cat /sys/bus/usb/devices/*/idVendor` 逐个设备查看厂商 ID。
- 模组不识别先确认模式：切换后 `lsusb` 的 VID:PID 是否变化，未变化则 usb-modeswitch 配置或模组锁卡问题。
