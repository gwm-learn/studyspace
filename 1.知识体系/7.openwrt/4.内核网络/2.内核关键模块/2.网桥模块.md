# Linux 网桥模块

# 概述

Linux 网桥（bridge）是一个内核实现的**二层交换机**：把多个网络接口挂到一个虚拟网桥上，转发依据是 MAC 地址表，不涉及 IP 路由。网桥模块在内核中表现为 `net/bridge/` 目录，核心数据结构是 `struct net_bridge` 和 `struct net_bridge_port`。

OpenWrt 中几乎所有 LAN 口都是靠网桥工作的：`/etc/config/network` 里的 `config device` + `option type 'bridge'` 把 `lan1`、`lan2`、`wlan0` 等接口桥成一个 `br-lan`。设备上的交换芯片端口通常注册为独立的 netdev，再被桥接。

# 网桥核心实现

## 1. 数据转发路径

网桥不创建新的协议栈入口，而是挂在**收包路径**上。收包经 `netif_receive_skb()` 时，会先检查设备是否属于某个网桥：

1. 网桥口收到帧 → `br_handle_frame()`（通过 `rx_handler` 挂载）。
2. 学习源 MAC：把 `src MAC + 入端口` 写入 FDB（Forwarding Database）转发表。
3. 查 FDB 找目的 MAC：
   - 命中且是**其他端口**：转发，通过 `br_forward()` 发往目标端口。
   - 命中且是**同一端口**：丢弃。
   - 未命中：向所有端口泛洪（广播/未知单播同此路径）。
4. 若目的 MAC 是**网桥自身地址**，交给协议栈（IP 层）处理，例如访问管理地址。

关键数据结构：`struct net_bridge_fdb_entry` 是 FDB 表项，记录 MAC、端口、老化时间（`ageing_time` 默认 300 秒）。`bridge fdb show` 可查看，`brctl` 是传统管理工具。

## 2. STP 生成树协议

网桥默认开启 STP（生成树），防止环路。`bridge/br_stp_*.c` 实现 BPDU 收发与状态机：

- 端口状态：Disabled、Listening、Learning、Forwarding、Blocking。
- OpenWrt 默认关闭 STP（`option stp '0'`），家用场景单网桥无环路，加快端口收敛。

## 3. 三层接口 br-lan

网桥本身也是一个 netdev（`br-lan`），可以配 IP、开启转发。给 br-lan 配 IP 后，网桥同时具备三层能力，即"桥上有 IP"，这是 OpenWrt 路由器默认形态。桥上的 IP 处理与二层转发互不干扰：二层帧走 FDB，本机目的 IP 的帧由 IP 层接收。

# ebtables

ebtables 是**二层防火墙**，基于 Netfilter 桥接钩子点，位于 `net/bridge/netfilter/`。它处理的包还没进 IP 层，因此能过滤 ARP、EAPOL 等非 IP 帧。

桥接框架在网桥路径上挂了 5 个特殊钩子点（`NF_BR_*`）：

- `NF_BR_PRE_ROUTING`：网桥口收帧后立即触发。
- `NF_BR_LOCAL_IN` / `NF_BR_LOCAL_OUT`：发给/来自本机的帧。
- `NF_BR_FORWARD`：转发帧。
- `NF_BR_POST_ROUTING`：从网桥口发出前。

典型用途：

- **过滤 ARP**：`ebtables -A FORWARD -p ARP --arp-opcode Request -j DROP`，防 ARP 欺骗。
- **放行 EAPOL**：`ebtables -A FORWARD -p 0x888e -j ACCEPT`，802.1X 认证帧。
- 注意：`br_netfilter` 模块让 IP 层的 iptables 也能作用于桥接帧（`bridge-nf-call-iptables` 参数），OpenWrt 防火墙常依赖它，转发性能会受影响。

# 桥接 + VLAN 组合

## 1. 内核 VLAN 子接口

`8021q` 模块把物理口拆成 VLAN 子接口（如 `eth0.1`、`eth0.2`），每个子接口是独立 netdev，可以各自桥接：

```
eth0.1 ─┐
eth0.2 ─┼─> br-lan（带 VLAN tag 的帧进入桥内）
wlan0 ──┘
```

这种模式下 VLAN tag 在进入网桥前就被 `8021q` 剥掉，桥内看到的都是无 tag 帧。多 VLAN 需要多个网桥或配合 `vlan_filtering`。

## 2. 网桥 VLAN 过滤（bridge vlan_filtering）

从 3.9 内核起，网桥自身支持 VLAN 过滤（`bridge vlan add` / `bridge vlan filter`），配置 `vlan_filtering 1` 后：

- 帧带 VLAN tag 进入网桥，由网桥按 `VID + 端口成员` 转发，不再需要 `8021q` 子接口。
- 每个端口有 **PVID**（默认 1）和 tagged/untagged 成员关系，`bridge vlan show` 查看。
- 一个网桥内可以同时承载多个 VLAN 的二层隔离，OpenWrt 高配设备用它替代多网桥方案。

## 3. 与 DSA 交换机配合

OpenWrt 常见设备上，物理端口走 DSA 框架（`drivers/net/dsa/`）：交换芯片的 CPU 端口和用户端口都注册为 netdev，用户端口直接进网桥，CPU 端口承载控制面。此时 VLAN 划分通常在 DSA 层用 `switch vlan` 配置完成，桥只负责端口聚合。

# OpenWrt 实践要点

- 查看网桥：`brctl show` 或 `bridge link`，`ip link show type bridge`。
- 查看 FDB：`bridge fdb show`，排查转发异常先看目的 MAC 是否在表里。
- 网桥转发性能优化：关闭 `bridge-nf-call-iptables`（`sysctl net.bridge.bridge-nf-call-iptables=0`）可明显提升吞吐。
