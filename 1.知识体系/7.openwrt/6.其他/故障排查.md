# OpenWrt 常见网络故障排查

## 一、日志查看

### 1.1 logread（OpenWrt 系统日志）
OpenWrt 使用 syslog-ng 或 logd 记录日志，`logread` 是统一的查看入口：

```bash
logread                          # 查看全部日志
logread -f                       # 实时跟踪（类似 tail -f）
logread | grep -i network        # 过滤网络相关日志
logread | grep -i -E 'ppp|dhcp'  # 过滤拨号与 DHCP 日志
```

日志默认保存在内存环形缓冲中，重启即丢失；需要持久化可配置 `log_file` 选项写入 `/var/log/`。

### 1.2 dmesg（内核日志）
```bash
dmesg | tail -50                 # 最近内核日志
dmesg | grep -i -E 'eth|usb|wlan'  # 网卡/驱动相关
```

`logread` 与 `dmesg` 结合，可区分问题是出在应用层（netifd、pppd、dnsmasq）还是内核层（驱动、PHY、链路）。

## 二、无法上网排查流程

### 2.1 分层排查思路
| 层次 | 检查内容 | 常用命令 |
|------|----------|----------|
| 链路层 | 网线、光猫、端口 UP | `ip link show`、`ethtool wan` |
| 网络层 | WAN 地址、默认路由 | `ifstatus wan`、`ip route` |
| 传输/应用层 | 网关连通、DNS 解析 | `ping`、`nslookup` |
| 转发层 | 防火墙、NAT 规则 | `nft list ruleset`、`iptables -t nat -L` |

### 2.2 具体排查步骤
1. **确认物理链路**：`ip link show` 查看 WAN 口是否为 UP，`ethtool wan` 查看协商速率。
2. **确认 WAN 是否拿到地址**：`ifstatus wan` 检查 up、address、gateway 字段；PPPoE 拨号看 `logread | grep ppp`。
3. **确认默认路由**：`ip route` 应存在指向网关的默认路由，缺失时检查 `/etc/config/network` 中 wan 接口配置。
4. **确认网关连通**：`ping -c 3 网关IP`，不通则问题在运营商侧或链路层。
5. **确认 DNS 解析**：`nslookup www.baidu.com`，失败进入第三节。
6. **确认转发与 NAT**：lan 侧 ping 通网关但外网不通，检查防火墙 zone 配置与 NAT masquerade 是否开启。

## 三、DNS 问题

### 3.1 常见症状
- 能 ping 通 IP 但打不开网页。
- 部分域名解析慢或失败。
- 客户端反复提示 DNS 错误。

### 3.2 排查命令
```bash
nslookup www.openwrt.org             # 使用默认 DNS
nslookup www.openwrt.org 223.5.5.5   # 指定公共 DNS 对比
logread | grep dnsmasq               # 查看 dnsmasq 日志
```

### 3.3 常见原因
- dnsmasq 未启动或配置错误：`/etc/init.d/dnsmasq status`。
- 上游 DNS 不可达：修改 `/etc/config/network` 中 wan 接口的 `dns` 选项。
- 本地 `/etc/hosts` 或 `dnsmasq.conf` 存在冲突条目。
- 运营商 DNS 劫持或故障：临时改用公共 DNS（114.114.114.114、223.5.5.5）验证。

## 四、DHCP 问题

### 4.1 常见症状
- 客户端无法获取 IP（一直显示 169.254.x.x）。
- 获取到 IP 却无法上网（网关或 DNS 分配错误）。

### 4.2 排查命令
```bash
logread | grep dnsmasq               # 查看 DHCP 分配记录
ps | grep dnsmasq                    # 确认 dnsmasq 进程存在
cat /tmp/dhcp.leases                 # 查看已分配的租约
```

### 4.3 常见原因
- dnsmasq 未运行或只监听错误接口：检查 `/etc/config/dhcp` 中 dhcp 节与 interface 对应关系。
- 接口地址未配置：DHCP 服务依赖 LAN 接口的静态 IP。
- 地址池耗尽：检查 `start`/`limit` 与网段内可用地址数。
- 上游光猫开启 DHCP 与路由器冲突：关闭光猫 DHCP 或错开网段。

## 五、PPPoE 拨号失败

### 5.1 常见症状
- WAN 状态显示 `connecting` 或 `protocol` 错误。
- 反复拨号、掉线重拨。

### 5.2 排查步骤
1. 查看拨号日志：`logread | grep -i ppp`，关注 `PAP authentication failed`、`Timeout waiting for PADO` 等关键字。
2. 确认账号密码：`uci show network.wan`，检查 username/password 是否有误。
3. 确认物理链路：PPPoE 依赖以太网链路先通，`ip link show` 确认端口 UP。
4. 更换拨号方式：部分 ISP 需要 VLAN 标签，检查 `/etc/config/network` 中 device 是否包含 `vid` 配置。

### 5.3 常见原因
- 账号密码错误或欠费。
- ISP 线路故障或光猫未注册。
- 拨号接口绑错网口或 VLAN 标签不对。
- 设备被运营商限速/封禁，MAC 绑定导致失败。

## 六、其他常见问题

### 6.1 网速慢
- 检查无线干扰与信道占用：`iw dev wlan0 survey dump`。
- 检查交换机协商速率：`ethtool lan1`，确认未降为 10M/100M。
- 检查 QoS/流量控制规则是否误限速。

### 6.2 频繁掉线
- 检查过热或供电不足（硬件层）。
- 查看 `logread` 中接口重启记录，确认 netifd 是否因 hotplug 反复触发。
- 确认运营商线路质量与拨号会话超时策略。

## 七、总结

排查遵循**自下而上**的顺序：链路、地址、路由、DNS、转发。善用 `logread` 与 `dmesg` 定位问题层次，再结合对应模块的配置逐项排除，是 OpenWrt 网络故障诊断的核心方法。
