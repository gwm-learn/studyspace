# OpenWRT 启动流程

OpenWRT 启动流程整体分为 **Bootloader → Linux 内核 → Preinit → Procd（主 init）→ 服务启动** 五大阶段，全程以 procd 作为 PID 1 进程，轻量、可定制、适合嵌入式场景。下面按顺序详细拆解。

## 一、Bootloader 阶段（U-Boot / CFE）

设备上电后，CPU 从 Flash 固定地址执行 Bootloader（常见为 U-Boot，Broadcom 平台常用 CFE）。

### 1. 硬件初始化（POST）

- 初始化 CPU、内存、Flash、串口、网络等基础硬件
- 检测内存、Flash 分区，建立基本硬件环境

### 2. 加载内核与设备树

从 Flash 读取 **内核镜像（zImage/uImage）** 与 **设备树（DTB）** 到 RAM。

典型命令（U-Boot）：

```bash
nand read ${kernel_addr_r} firmware 0x1000000
nand read ${fdt_addr_r} device-tree
bootz ${kernel_addr_r} - ${fdt_addr_r}
```

### 3. 传递启动参数（bootargs）

内核命令行示例：

```
noinitrd root=/dev/mtdblock2 rootfstype=squashfs,jffs2 console=ttyS0,115200 init=/etc/preinit
```

关键参数：

- `root`：根文件系统所在分区（如 mtdblock2）
- `rootfstype`：文件系统类型（只读 SquashFS + 可写 JFFS2/UBIFS）
- `init`：内核启动后第一个执行的用户程序（默认 `/etc/preinit`）
- `console`：串口输出配置

## 二、Linux 内核启动阶段

内核解压、自举，完成硬件驱动加载与根文件系统挂载。

### 1. 内核自举（start_kernel）

- 执行 `start_kernel`，初始化调度、内存、中断、进程管理
- 扫描 MTD 分区，挂载 **只读 SquashFS 根文件系统**（含 `/etc`、`/bin`、`/sbin`）

### 2. 加载内核模块

执行 `/sbin/kmodloader`，按 `/etc/modules-boot.d/` 加载必要驱动（网络、USB、Flash 等）。

### 3. 启动第一个用户进程

内核完成初始化后，执行 `init=` 指定的程序（默认 `/etc/preinit`），进入用户空间。

## 三、Preinit 阶段（系统预初始化）

`/etc/preinit` 是内核启动的第一个脚本，负责搭建最小运行环境，为 procd 做准备。

### 1. 核心任务

- **挂载虚拟文件系统**：

  ```bash
  mount -t proc proc /proc
  mount -t sysfs sysfs /sys
  mount -t tmpfs tmpfs /tmp
  ```

- 初始化 `/dev`（mdev/udev），创建设备节点
- 挂载 **只读 SquashFS** 到 `/rom`、**可写 JFFS2/UBIFS** 到 `/overlay`
- 合并 `/rom` 与 `/overlay`，形成可读写的根文件系统（OverlayFS）
- **进入 Failsafe 模式**（可选，按复位键触发）：
  - 配置默认 IP `192.168.1.1/24`
  - 启动 telnet，用于系统修复

### 2. Preinit 脚本执行顺序

- 入口：`/etc/preinit`
- 执行 `/lib/preinit/` 下按序号排列的脚本（如 `00_sysfs`、`10_system`、`99_10_run_init`）
- 最后执行 `exec /sbin/procd`，替换当前进程，进入 procd 主阶段

## 四、Procd 主阶段（PID 1 进程）

`/sbin/procd` 成为 PID 1，是 OpenWRT 的 init 系统 + 服务管理器 + 热插拔处理 + 日志收集 一体化组件。

### 1. 解析 /etc/inittab

默认内容：

```
::sysinit:/etc/init.d/rcS S boot
::askconsole:/bin/ash --login
```

- `sysinit`：系统初始化入口，执行 `/etc/init.d/rcS S boot`
- `askconsole`：串口控制台，启动 ash shell

### 2. 执行 /etc/init.d/rcS

`rcS` 遍历 `/etc/rc.d/` 下所有以 `S` 开头的脚本（按数字顺序），执行 `start` 命令。

示例：`S40network`、`S50dropbear`、`S60dnsmasq`、`S96led` 等。

### 3. Procd 核心功能

- **服务管理**：管理 `/etc/init.d/` 下所有服务，支持启动 / 停止 / 重启 / 状态查询
- **热插拔（hotplug）**：处理 USB、网络接口、存储等设备插拔事件
- **日志收集**：通过 ulog 收集内核与用户空间日志，输出到 `/var/log/messages` 或远程服务器
- **看门狗（watchdog）**：监控系统健康，异常时自动重启

## 五、服务启动与系统就绪

`/etc/rc.d/S*` 脚本按顺序启动核心服务，系统进入可用状态。

### 1. 关键服务启动顺序（典型）

- `S02nvram`：加载 NVRAM 配置
- `S10boot`：系统基础初始化
- `S40network`：配置网络接口、IP、路由
- `S45firewall`：加载防火墙规则
- `S50dropbear`：启动 SSH 服务
- `S60dnsmasq`：启动 DNS/DHCP 服务
- `S96led`：配置 LED 状态
- `S98sysntpd`：同步系统时间

### 2. 系统就绪

所有服务启动完成，procd 进入事件循环，处理热插拔、服务状态监控。

用户可通过 Web UI（LuCI）、SSH、串口访问设备。

## 六、完整启动流程总览（时序）

```
上电 → Bootloader（U-Boot/CFE）
Bootloader → 加载内核 + DTB → 传递 bootargs
内核 → 自举 → 挂载 SquashFS → 加载模块 → 执行 /etc/preinit
Preinit → 挂载虚拟文件系统 → 初始化 /dev → 挂载 /rom//overlay → exec /sbin/procd
Procd（PID 1）→ 解析 /etc/inittab → 执行 /etc/init.d/rcS S boot
rcS → 按序执行 /etc/rc.d/S* → 启动所有服务
Procd 进入事件循环 → 系统就绪
```

## 七、调试与自定义启动

### 1. 查看启动日志

```bash
dmesg          # 内核日志
logread        # 系统日志（procd 收集）
```

### 2. 添加自启动服务

- 编写脚本到 `/etc/init.d/`，添加 `START=XX` 与 `STOP=XX`
- 启用服务：`/etc/init.d/xxx enable`（自动创建 `/etc/rc.d/SXXxxx` 软链接）
- 手动启动：`/etc/init.d/xxx start`

### 3. 进入 Failsafe 模式

开机时快速按 **复位键 3–5 次**。

系统以默认 IP `192.168.1.1` 启动，仅开启 telnet，用于修复配置。
