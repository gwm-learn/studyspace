# OpenWrt 热插拔（hotplug）详解

## 1. 热插拔是什么？

设备插入 / 拔出 / 状态变化时，系统自动触发脚本执行：

- USB 设备插入 / 移除
- 网口 up/down
- 网卡、WiFi 接口出现 / 消失
- 分区挂载、按钮按下
- 3G/4G 模块上电 / 拨号

OpenWrt 用 **procd** 统一管理热插拔，不再依赖旧的 udev/hotplug2。

## 2. 热插拔核心架构

### 2.1 负责组件

- **procd（PID=1）**：接收内核事件 → 分发到脚本
- **hotplug.json**：定义哪些事件触发哪些脚本
- **/etc/hotplug.d/xxx/**：按类别存放脚本
- 内核通过 netlink 发送 uevent 给用户态

### 2.2 事件流向

```
内核 uevent → procd → 匹配 hotplug.json → 运行对应目录脚本
```

## 3. 热插拔目录结构（必须记住）

```
/etc/hotplug.d/
├── 00-button/      # 按钮事件
├── 10-usb/         # USB 设备
├── 20-net/         # 网络接口 up/down/add/remove
├── 40-tty/         # 串口/modem
├── 50-block/       # 块设备（U盘、SD、SATA）
├── iface/          # 网络接口（上层逻辑，如wan up）
├── dhcp/           # DHCP 事件
└── ...
```

脚本执行顺序：按文件名数字从小到大执行。

## 4. 最关键配置：/etc/hotplug.json

procd 靠它决定什么事件进哪个目录。

典型片段：

```json
[
    {
        "comment": "network devices",
        "subsystem": "net",
        "env": { "DEVPATH": "" },
        "rules": [
            {
                "directory": "/etc/hotplug.d/20-net"
            }
        ]
    },
    {
        "comment": "usb devices",
        "subsystem": "usb",
        "env": { "DEVPATH": "" },
        "rules": [
            {
                "directory": "/etc/hotplug.d/10-usb"
            }
        ]
    },
    {
        "comment": "block device",
        "subsystem": "block",
        "env": { "DEVPATH": "" },
        "rules": [
            {
                "directory": "/etc/hotplug.d/50-block"
            }
        ]
    }
]
```

## 5. 热插拔环境变量（开发必用）

热插拔脚本运行时会自带大量环境变量，不用解析 sysfs。

### 通用：

- `ACTION`：add / remove / change
- `SUBSYSTEM`：usb / net / block
- `DEVNAME`：设备名（eth0、sda、ttyUSB0）
- `DEVPATH`：设备路径
- `INTERFACE` / `MACADDR`（net）
- `MAJOR` `MINOR`（设备号）

### 网口常用：

- `INTERFACE`：eth0、wlan0
- `ACTION`：add / remove / ifup / ifdown

### 块设备：

- `DEVNAME`：sda1、mmcblk0p1
- `ACTION`：add / remove

## 6. 最常用 4 类热插拔示例（可直接背）

### 6.1 USB 设备插入 /etc/hotplug.d/10-usb/99-myusb

```sh
#!/bin/sh
[ "$ACTION" = "add" ] || exit 0

logger "USB 设备插入: $DEVNAME"
```

### 6.2 网口状态变化 /etc/hotplug.d/20-net/99-mynet

```sh
#!/bin/sh
[ "$INTERFACE" = "eth0.2" ] || exit 0

if [ "$ACTION" = "ifup" ]; then
    logger "WAN 口上线"
fi
```

### 6.3 U 盘挂载 /etc/hotplug.d/50-block/99-mydisk

```sh
#!/bin/sh
[ "$ACTION" = "add" ] || exit 0
[ -b "/dev/$DEVNAME" ] || exit 0

mkdir -p /mnt/usb
mount /dev/$DEVNAME /mnt/usb
logger "U盘已挂载"
```

### 6.4 按钮事件 /etc/hotplug.d/00-button/99-mybtn

```sh
#!/bin/sh
[ "$BUTTON" = "reset" ] || exit 0
[ "$ACTION" = "pressed" ] || exit 0

logger "复位键按下"
```

## 7. 上层逻辑热插拔（iface）

区别于内核 net 事件，iface 是网络上层逻辑事件（如 wan 获得 IP）。

### 目录：

```
/etc/hotplug.d/iface/
```

### 常用变量：

- `ACTION`：ifup / ifdown / update
- `INTERFACE`：wan / lan
- `DEVICE`：eth0.2
- `IPADDR`

### 示例：

```sh
[ "$INTERFACE" = "wan" ] || exit 0
[ "$ACTION" = "ifup" ] || exit 0

logger "WAN 已上线，IP: $IPADDR"
```

## 8. 如何调试热插拔（非常实用）

### 8.1 实时看事件

```sh
logread -f
```

### 8.2 手动触发一个热插拔（测试脚本）

```sh
ubus call service event '{
    "type":"net",
    "action":"ifup",
    "interface":"wan"
}'
```

### 8.3 看 procd 是否正常

```sh
pgrep procd
```

### 8.4 查看内核 uevent

```sh
uevent monitor
```

## 9. 常见面试 / 开发考点

- OpenWrt 热插拔管理者是 **procd**
- 配置文件：`/etc/hotplug.json`
- 脚本目录：`/etc/hotplug.d/` 子系统 /
- 执行顺序：文件名数字从小到大
- 关键变量：`ACTION`、`SUBSYSTEM`、`DEVNAME`、`INTERFACE`
- 内核事件 → uevent → procd → 脚本
- `net` 是内核网口；`iface` 是上层网络逻辑事件

## 10. 极简记忆版

- procd 负责热插拔
- hotplug.json 决定事件走向
- `/etc/hotplug.d/xxx/` 放脚本
- 脚本按数字顺序执行
- 环境变量直接拿设备信息
- logread 调试
