# 概述
运输层协议为运行在不同主机上的应用进程之间提供了逻辑通信功能。从应用程序的角度看，通过逻辑通信，运行不同进程的主机好像直接相连一样   
运输层协议是在端系统中而不是在路由器中实现。   
运输层发送运输层报文段。网络路由器仅仅作用于数据包的网络层字段，即其不会检查封装在该数据报的运输层报文段的字段。

# 多路复用与多路分解
将运输层报文段中的数据交付到正确的套接字的工作称为多路分解。   
在源主机从不同套接字中收集数据块，并为每个数据块封装上首部信息从而生成报文段，然后将报文段传递到网络层的工作称为多路复用。

# UDP
用户数据报协议 不可靠，无连接的服务。   
UDP只是做了运输协议能够做的最少工作。除了复用/分解功能及少量的差错检测外，它几乎没有对IP增加别的东西。   
DNS是一个通常使用UDP的应用层协议的例子。   
UDP首部有四个字段，八个字节，每个字段由两个字节组成。源端口号、目的端口号、长度、校验和。

# TCP

## 概述
传输控制协议（TCP）提供可靠、面向连接的服务。

## 关键概念
- **ARQ**：自动重传请求协议，确保数据可靠传输。
- **MSS**：最大报文段长度，指 TCP 报文段中应用层数据的最大长度。
- **MTU**：最大传输单元，指链路层帧能承载的最大数据量。
- **基于 MTU 设置 MSS**：MSS 通常根据 MTU 计算，以避免 IP 分片。

## 连接建立与断开

### 三次握手（建立连接）
#### 角色
- **客户端**：主动发起连接
- **服务端**：被动等待连接

#### 标志位
- **SYN**：我要建立连接
- **ACK**：我收到了

#### 过程
1. 客户端 → 服务端：`SYN=1`（我想连你）
2. 服务端 → 客户端：`SYN=1, ACK=1`（收到，我同意）
3. 客户端 → 服务端：`ACK=1`（收到你的同意）

→ 连接建立成功，可以开始传输数据。

#### 为什么要 3 次？
确保双方的发送、接收能力都正常：
- 客户端：我能发、能收
- 服务端：我能发、能收

少一次都无法确认双方都正常。

### 四次挥手（断开连接）
#### 标志位
- **FIN**：我要关闭连接
- **ACK**：我收到了

#### 过程
1. 客户端 → 服务端：`FIN=1`（我发完了，要关了）
2. 服务端 → 客户端：`ACK=1`（收到你要关）
   - （但服务端可能还有数据没发完，所以不能马上关）
3. 服务端 → 客户端：`FIN=1`（我也发完了，关吧）
4. 客户端 → 服务端：`ACK=1`（收到，关闭）

→ 连接正式关闭。

#### 为什么是 4 次？
因为关闭是双向独立的：
- 客户端先关发送
- 服务端可能还要发数据，发完再关自己的

所以必须分开确认，一共 4 步。

## 记忆口诀（面试直接背）
- **三次握手**：SYN → SYN+ACK → ACK
- **四次挥手**：FIN → ACK → FIN → ACK
